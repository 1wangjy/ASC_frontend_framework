# 改造记录：新页面对接后端（初始提交 API 表面）

> 日期：2026-08-07
> 目标：使新页面（AscQaView、DocumentLibraryView、KnowledgeExplorerView）对接初始提交 `f8b9ee4` 的后端 API
> 原则：不改后端，只改前端，最小改动

---

## 改造背景

初始提交的后端 API 没有 `GET /api/graph/project/list` 接口，导致新页面无法获取项目列表。其余 API（`codGraphRAGQuery`、`listPdfFiles`、`getGraphData` 等）均存在。

## 核心策略

**项目注册表（Project Registry）**：在旧工作流（MainView.vue）创建项目时，将 `project_id` 存入 `localStorage`；新页面加载时从 `localStorage` 读取 ID，用 `getProject(projectId)` 逐个获取。

## 关键设计决策

1. **为什么不用 `listBaseMetadata()` 替代 `listProjects()`？**
   `listBaseMetadata` 返回的是 base metadata 文件列表，语义不同，不保证包含所有项目。

2. **为什么不在 `AscQaView.vue` 中保留 `listProjects` 作为 fallback？**
   因为后端确定没有这个接口，保留只会增加复杂度。如果将来后端新增了该接口，可以在 `projectRegistry.js` 中增加远程优先策略。

3. **为什么 `Step4Report.vue` 的 `reportTaskId` 轮询必须移除而不是修复？**
   因为 `POST /api/report/generate/status` 接口不存在，且初始提交的 `GET /api/report/generate/status?report_id=xxx` 只支持 `report_id` 参数，不支持 `task_id`。保持旧轮询方式（`getAgentLog`/`getConsoleLog`）最稳定。
