# ASC 前端持续研究工作流设计

日期：2026-08-09

## 1. 目标与结论

ASC 前端不是一组彼此独立的展示页面，而是一条由 5002 后端驱动的科研工作流：

```text
文献管理
  -> 选择或上传文献
  -> 创建知识图谱项目
  -> 本体生成与图谱构建
  -> 获得 project_id 和 graph_id
  -> 针对指定图谱问答
  -> 仿真运行
  -> 报告生成
  -> 深度互动
```

本次设计保留问答、文献管理、仿真、报告和深度互动，并解决两个主要问题：

1. 图谱构建在 `MainView` 中启动后，用户切换页面就看不到进度。
2. “新建问答”位于“历史问题”标题和列表之间，视觉层级突兀。

最终采用以下方案：

- 顶级导航仍只保留“问答首页”和“文献管理”。
- 不新增一个与问答、文献平级的“图谱构建平台”。
- 在所有页面共用的应用外壳中增加“全局任务状态”，持续显示图谱构建进度。
- 点击全局任务状态，返回现有 `/process/:projectId` 详细流程页。
- 图谱构建完成后刷新可用图谱，并提供“去问答”操作，不在用户浏览其他页面时强制跳转。
- 将“新建问答”移动到右侧问题面板最上方，位于问题列表标题之前。
- 不修改 5002 后端代码，也不修改 3001 前端。

## 2. 为什么不新增独立的图谱模块

图谱构建是“文献到问答”之间的后台任务，不是用户最终消费内容的独立业务中心。新增一个平级模块会产生第二套入口、第二套状态展示和重复页面，进一步加剧当前“两套前端逻辑没有对齐”的问题。

现有 `MainView` 已经承担以下职责：

- 创建或打开图谱项目；
- 本体生成；
- 发起图谱构建；
- 查询项目和任务状态；
- 加载完成后的图谱；
- 进入指定图谱问答。

因此保留它作为“任务详情页”，只在应用外壳中增加一个轻量的跨页面任务入口。这样既能一直看到进度，又不会复制现有流程。

## 3. 页面和导航结构

### 3.1 顶级导航

只显示：

- 问答首页 `/`
- 文献管理 `/documents`

仿真、报告和深度互动继续保留，但属于图谱问答后的高级流程，不占用顶级导航：

- 仿真配置 `/simulation/:simulationId`
- 仿真运行 `/simulation/:simulationId/start`
- 报告 `/report/:reportId`
- 深度互动 `/interaction/:reportId`

图谱流程页 `/process/:projectId` 是从文献管理、全局任务状态或项目上下文进入的任务详情页，也不作为永久顶级入口。

### 3.2 全局图谱任务状态

在所有路由共用的 `AscShell` 中加入轻量状态入口。它始终可见，但不遮挡主要内容。

状态入口至少显示：

- 当前活动任务数量；
- 最近或当前任务名称；
- 阶段：准备、本体生成、图谱构建、完成或失败；
- 后端返回的真实进度和消息；
- 连接状态：正常、重连中或已断开。

点击入口后展开任务列表。每项提供：

- “查看进度”：打开 `/process/:projectId`；
- “去问答”：仅在图谱完成并取得有效 `project_id`、`graph_id` 后出现；
- “重试连接”：仅重新请求后端状态，不伪造或重启后端任务。

当存在多个任务时，列表分别展示，不自动用最新任务覆盖用户正在关注的任务。

### 3.3 问答右侧问题面板

排列调整为：

```text
[ + 新建问答 ]

示例问题 / 最近问答
问题列表
查看更多
```

“新建问答”移动到面板最上方，和下面的问题列表形成两个清晰区块。

当前问题列表来自前端静态配置，并不是真实后端问答历史，因此在没有真实历史接口前，不得标为“历史问题”。本次默认恢复为“示例问题”。如果仅记录当前浏览器会话中的提问，则必须明确标为“本次会话”，不能暗示它是跨设备、跨登录保存的后端历史。

## 4. 前端组件和职责

### 4.1 `graphTaskMonitor`

新增一个独立的响应式任务监控层，生命周期高于具体页面，由 `AscShell` 启动和停止。

它只负责：

- 请求后端项目列表，并按项目中的 `graph_build_task_id` 查询进行中的单任务状态；
- 将任务与对应项目关联；
- 维护连接状态和最后一次成功同步时间；
- 根据任务活跃状态调整轮询频率；
- 向页面暴露只读任务列表和刷新操作；
- 在任务完成时触发项目列表刷新通知。

它不负责：

- 创建图谱项目；
- 启动图谱构建；
- 生成模拟进度；
- 修改任务结果；
- 代替 `MainView` 展示完整步骤。

### 4.2 `GlobalGraphTaskIndicator`

该组件只消费 `graphTaskMonitor` 的状态，负责显示任务入口、任务列表、错误提示和跳转操作。业务请求和轮询逻辑不直接写在展示组件中。

### 4.3 `MainView`

继续作为图谱工作流详情页。它保留现有创建、构建、加载图谱和进入问答的逻辑。

从其他页面返回时，`MainView` 使用路由中的 `projectId` 重新查询后端项目。如果项目仍在本体生成或图谱构建中，则恢复详情进度展示；如果已完成，则加载图谱；如果失败，则显示后端返回的失败原因和允许的前端操作。

图谱构建完成时：

- 用户仍停留在 `MainView`：可以继续显示完成态，并由用户点击进入问答；
- 用户已切到其他页面：全局任务状态变为完成并显示“去问答”，不强制改变当前路由。

### 4.4 问答项目选择器

问答只能针对后端确认存在、且拥有有效 `project_id` 和 `graph_id` 的项目发起。全局任务完成后通知问答项目列表重新请求后端，但不能仅凭前端缓存把任务标记为可问答。

发送问题前继续执行项目范围校验；响应返回后继续校验后端实际解析到的项目和图谱范围，防止后端回退到其他图谱时展示错误答案。

## 5. 后端连接与实时状态

### 5.1 连接方式

开发环境统一使用同源 `/api`：

```text
浏览器 http://localhost:3000
  -> Vite /api 代理
  -> http://127.0.0.1:5002
```

不在组件中散落写死的 `http://127.0.0.1:5002`。生产或特殊部署继续通过 `VITE_API_BASE_URL` 配置。

本设计使用当前已经验证可用的接口，不要求修改后端：

- `GET /api/graph/project/list`
- `GET /api/graph/project/:projectId`
- `GET /api/graph/task/:taskId`
- `GET /api/graph/data/:graphId`
- 现有本体生成、图谱构建、问答、仿真和报告接口

后端虽然声明了 `GET /api/graph/tasks`，但 2026-08-09 对正在运行的 5002 实测为 HTTP 500，错误为 `AttributeError: 'dict' object has no attribute 'to_dict'`。由于本次禁止修改后端，全局监控不得依赖该接口。监控先通过项目列表识别 `ontology_generating`、`graph_building`、`graph_completed` 和 `failed` 状态，再只对带 `graph_build_task_id` 的构建中项目请求单任务状态。这样既绕开已知故障，又保持项目与任务天然对应。

### 5.2 轮询策略

5002 后端当前提供 HTTP 状态查询而不是 WebSocket，因此“实时”采用受控轮询：

- 存在进行中任务：约每 1.5 秒查询一次；
- 没有进行中任务：约每 12 秒进行轻量同步；
- 页面重新获得焦点、浏览器恢复在线、用户手动刷新：立即同步一次；
- 页面隐藏时降低频率，避免无意义请求；
- 每轮请求可取消或带序号，旧响应不得覆盖新状态。

具体间隔可以在实施时集中为常量，但不能在多个组件中各自创建重复轮询器。

### 5.3 断线和恢复

网络失败时：

- 保留最后一次成功获取的任务状态；
- 明确标记为“连接中断/正在重连”，不得继续播放虚假进度；
- 使用退避重试，最长间隔不超过约 15 秒；
- 连接恢复后立即重新获取任务、项目和可用图谱。

所有请求拦截器、预览和下载 URL 构造都必须安全读取浏览器存储。即使浏览器禁止 `localStorage`，基础后端请求和任务展示仍能运行。

### 5.4 能保证与不能保证的边界

前端能够保证：

- 切换前端页面时，任务状态入口不消失；
- 刷新 3000 页面后，从 5002 重新获取仍存在的任务和项目；
- 5002 暂时离线后，前端显示真实断线状态并自动恢复连接；
- 后端任务仍存在时，恢复显示其真实进度；
- 只有后端确认图谱存在时才允许进入定向问答。

在不修改后端的前提下，前端不能保证 5002 进程重启后仍保留内存中的任务。若后端重启导致任务记录丢失，前端只能依据项目最终状态恢复：已完成则加载图谱；未完成或失败则提示用户重新进入流程或按后端允许方式重试。任务本身要跨后端重启持续运行，需要后端增加任务持久化，不属于本次范围。

## 6. 数据权威和本地状态

- 后端项目、任务和图谱状态是唯一权威来源。
- `localStorage` 只保存可选的用户偏好或最近选择，不能作为任务完成依据。
- 路由参数用于定位项目，不代表该项目当前仍有效；进入页面后必须重新向后端确认。
- 组件卸载可以停止本组件的局部展示逻辑，但不能改变后端任务状态。
- 全局任务监控层不自动提交图谱、问答、仿真或报告请求，避免页面跳转或重连造成重复任务。

## 7. 高级流程保留方式

仿真、报告和深度互动全部保留，并继续使用后端返回的真实标识串联：

```text
project_id + graph_id
  -> simulation_id
  -> report_id
  -> 深度互动
```

这些页面不是死亡代码，也不应因为顶级导航精简而删除。用户应从已完成图谱或相应结果页进入它们。

首期全局状态入口只监控本体和图谱任务，结构上保留任务类型字段，以后可以在不改变外壳组件接口的情况下增加仿真和报告任务状态。首期不同时重写三套任务流程，避免扩大风险。

## 8. 错误处理原则

- 5002 无法连接：显示连接失败和重试状态，保留上次数据但标记为旧数据。
- 项目或图谱已删除：清空失效选择，刷新后端项目列表，由用户手动选择，不自动向其他图谱发送原问题。
- 任务查询不到但项目已完成：按项目中的有效 `graph_id` 加载完成结果。
- 任务查询不到且项目未完成：提示任务状态不可恢复，不伪装完成。
- 问答范围与请求范围不一致：拒绝展示答案并要求刷新选择。
- 组件卸载或路由切换：取消页面级请求；全局监控继续运行。
- 重复点击：创建、构建和发送操作在请求进行中禁用，避免重复后端任务。

## 9. 验收标准

### 9.1 核心流程

1. 在文献管理选择文献并进入图谱流程，能够通过 3000 的 `/api` 代理调用 5002。
2. 启动图谱构建后切换到问答首页或文献管理，全局任务状态仍显示同一个后端任务和真实进度。
3. 刷新浏览器后，任务仍存在时能从 5002 恢复显示。
4. 点击“查看进度”能回到正确的 `/process/:projectId`。
5. 图谱完成后，全局状态出现“去问答”；问答选择器刷新并能选择对应图谱。
6. 问答请求包含正确的 `project_id` 和 `graph_id`，响应范围不匹配时不显示答案。

### 9.2 异常和恢复

1. 停止 5002 后，3000 显示断线而非假进度；重新启动 5002 后自动恢复连接。
2. 后端删除项目或改变 `graph_id` 后，前端清理失效选择并要求手动选择。
3. 禁止 `localStorage` 时，项目列表、任务列表和基础 API 请求仍能工作。
4. 多个图谱任务并行时，任务列表不串项目、不互相覆盖。
5. 快速切换页面或连续刷新时，不产生重复构建请求。

### 9.3 页面与回归

1. “新建问答”位于问题列表标题上方。
2. 静态问题列表显示为“示例问题”，不冒充后端历史。
3. 现有仿真、报告和深度互动路由仍能进入并调用原有 5002 接口。
4. 3001 前端和 5002 后端文件无修改。
5. 前端构建、单元测试和关键浏览器流程通过。

## 10. 非目标

本次不做：

- 修改 5002 后端代码或接口；
- 修改 3001 前端；
- 新建第二套图谱构建工作台；
- 将 HTTP 轮询改成 WebSocket；
- 伪造跨设备问答历史；
- 让前端保证后端进程重启后内存任务继续执行；
- 重写仿真、报告和深度互动页面。

## 11. 实施边界

实施应按以下顺序进行，以保持每一步都能连接 5002 并独立验证：

1. 补齐任务查询适配器和安全存储访问测试；
2. 实现独立的全局任务监控状态层；
3. 在 `AscShell` 加入全局任务状态组件；
4. 调整 `MainView` 完成后的交互，不在后台完成时强制跳转；
5. 将图谱完成事件与问答项目列表刷新对齐；
6. 调整右侧问题面板布局和真实命名；
7. 回归仿真、报告、互动和 3000 -> 5002 真实连接。

每一步必须先写失败测试，再完成最小实现；最终使用真实 5002 做连接和浏览器流程验证。后端与 3001 只做只读验证，不参与修改。
