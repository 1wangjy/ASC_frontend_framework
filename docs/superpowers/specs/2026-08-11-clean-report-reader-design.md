# 独立报告阅读页设计

## 目标

把 `/report/:reportId` 从旧的 NEXUS 五步工作流页面中拆出来，改为专门阅读单份报告的页面。用户进入报告详情后，只看到报告名称、生成状态和报告正文，不再看到图谱面板、五步进度条、工作台切换、Agent 时间线或控制台日志。

报告继续由后端生成和保存。前端只读取真实 `report_id` 对应的数据，不生成假报告、不覆盖报告，也不触发重新生成。

## 已确认的交互

1. 报告显示名使用“`图谱项目名 · 研究报告`”。
2. 后端生成的原始报告标题和副标题保留，显示在项目报告名下方，避免丢失具体研究主题。
3. 报告生成中仍可打开详情页，但只显示简洁的生成状态、章节进度和已经生成的章节。
4. 报告完成后，页面自动切换为纯报告阅读状态。
5. 页面保留“返回报告列表”入口。
6. 报告失败时显示明确错误和重新读取按钮，不提供重新生成按钮。

## 页面结构

### 报告中心 `/reports`

每张报告卡片的主标题改为“`图谱项目名 · 研究报告`”。后端返回的报告标题作为研究主题或摘要展示。卡片继续显示状态、时间和真实 `report_id`，点击后进入对应报告详情。

### 报告详情 `/report/:reportId`

页面只保留以下区域：

- 顶部操作栏：返回报告列表、报告状态。
- 报告封面：图谱项目名、固定“研究报告”名称、后端原始标题与副标题。
- 生成进度：仅在报告未完成时显示章节完成数量和简洁进度条。
- 报告正文：按后端章节顺序显示 Markdown 内容。
- 错误状态：加载失败或生成失败时显示错误和重新读取操作。

删除以下旧工作流界面：

- 图谱关系可视化面板。
- “图谱 / 双栏 / 工作台”切换器。
- “Step 4/5 报告生成”步骤头和五步流程条。
- Agent 工具调用时间线、原始输出和控制台日志面板。
- 从报告页直接进入旧“深度互动”的按钮。

## 数据关联

前端按以下顺序解析图谱项目名称：

1. 使用报告的 `graph_id` 匹配现有逻辑图谱项目。
2. 若没有匹配，再使用报告的 `simulation_id` 匹配逻辑图谱项目。
3. 详情页还可通过 `report -> simulation -> project` 的现有只读关系补充项目名称。
4. 仍无法匹配时使用“未关联图谱 · 研究报告”，但不隐藏真实报告。

项目名称只影响显示，不回写后端报告，也不修改 `report_id`。

## 报告内容读取

报告详情统一通过现有只读接口读取：

- `GET /api/report/<report_id>`：读取报告元信息、完整 Markdown 和状态。
- `GET /api/report/<report_id>/sections`：读取已经保存的章节。
- `GET /api/report/<report_id>/agent-log`：报告生成中增量获取章节内容。
- `POST /api/report/generate/status`：只有路由带有真实 `taskId` 时查询生成任务状态；该请求只查询状态，不创建报告。

优先显示后端保存的完整 Markdown；完整正文尚未就绪时，使用章节接口和增量日志拼出当前已生成章节。生成完成后重新读取一次报告详情和章节，保证页面内容以后端最终保存结果为准。

## 组件边界

- `ReportView.vue`：只负责路由参数、项目名称关联和页面级加载状态。
- 新的报告阅读组件：负责报告封面、进度、章节正文和错误显示。
- 新的报告阅读模型：规范化报告状态、项目报告名、章节排序和完成进度，保持为可独立测试的纯函数。
- 现有 `Step4Report.vue`：不再由报告路由使用；必要的 Markdown 渲染逻辑提取后删除这套旧工作流组件，避免继续维护两套报告界面。

## 状态与生命周期

- `completed`：显示最终保存的完整报告，不启动生成轮询。
- `generating / processing / running / pending`：启动单实例轮询，显示已完成章节；页面卸载或报告 ID 改变时停止旧轮询。
- `failed / error`：停止轮询，显示后端错误，不自动重试生成。
- 路由切换后重新进入报告页时，从后端恢复报告内容；不依赖 `localStorage` 保存正文。

## 安全与错误处理

- 报告阅读页不得调用 `/api/report/generate`。
- 不提供“重新生成”或 `force_regenerate` 操作。
- 旧请求晚返回时不得覆盖新 `reportId` 的页面状态。
- Markdown 渲染沿用受控前端渲染规则，不直接执行后端返回的脚本或事件属性。
- 项目名称关联失败、章节暂缺和完整 Markdown 暂缺应分别降级，不误报为“没有报告”。

## 测试与验收

1. 报告中心与详情页都显示“`图谱项目名 · 研究报告`”。
2. `/report/:reportId` 不再渲染图谱面板、五步流程条、工作台切换或控制台日志。
3. 已完成报告直接显示后端保存的正文，且不启动生成任务状态轮询。
4. 生成中报告显示简洁章节进度，并能随着真实后端返回更新。
5. 生成完成后重新读取最终报告并进入纯阅读状态。
6. 报告失败、接口失败、项目未匹配都有明确且不同的界面反馈。
7. 从报告详情可以返回 `/reports`，刷新详情页仍能从后端恢复。
8. 任何报告中心和报告详情操作都不发起新的报告生成、删除或覆盖请求。
9. 不修改后端代码，现有单图谱单报告约束继续有效。
