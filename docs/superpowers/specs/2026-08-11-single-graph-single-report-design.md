# 一图一报告前端约束设计

## 目标

每组文献形成一个逻辑图谱项目。项目只有一个最终 Professional Graph；该图谱只允许形成一份完成报告；全站只保留一个问答平台，通过选择图谱切换其唯一报告上下文。

## 本次实现范围

本次只落实“禁止重新生成报告”，不在同一改动中新增报告生成侧边栏或迁移深度互动页面。

- 报告生成请求必须固定携带 `force_regenerate: false`，调用者不能覆盖。
- 进入模拟结果页时查询当前 `simulation_id` 是否已有完成报告。
- 已有完成报告时，按钮改为“查看已有报告”，点击后直接进入原 `report_id`，不得发送生成请求。
- 如果生成接口返回 `already_generated: true`，同样复用返回的 `report_id`。
- 报告生成失败仍允许重试；“禁止重新生成”只针对已经存在的完成报告。

## 数据边界

当前后端以 `simulation_id` 查询唯一报告，前端复用以下接口：

- `GET /api/report/check/:simulation_id`：判断是否已有报告。
- `POST /api/report/generate`：固定 `force_regenerate=false`。
- 返回的 `report_id`：进入唯一报告页面。

浏览器内按钮防重只能避免普通重复操作。多浏览器、刷新期间并发请求的绝对唯一性仍应由后端数据库唯一约束最终保证；本次不修改后端。

## 后续架构

后续拆分为“图谱构建”“报告生成”“问答首页”三个独立页面时，继续保持：

`文献集合 -> 逻辑图谱项目 -> 最终图谱 -> 唯一报告 -> 统一问答平台`
