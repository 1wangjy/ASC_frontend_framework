# ASC 回答评估区域设计说明

日期：2026-08-03  
状态：待用户确认后实施

## 1. 背景

当前问答页右侧的“证据与评估”区域包含引用来源、静态专家分数、维度进度条和摘要片段。新的回答评估需求要求：保留回答引用证据，但移除旧的静态评分表现，将右侧区域改造成可操作的“评审工作台”，并提供“人工评估”和“LLM 评估”两个可切换子区域。

本设计依据 `回答评估子功能.docx`，并结合用户确认的方案 A 重新组织信息层级，不复制参考系统的原始布局。

## 2. 已确认的核心定义

- 评估对象是模型生成的回答，不是文献。
- 人工评估是二分类评审，结果文案固定为：`准确`、`不准确`。
- 不使用“正确 / 不正确”，也不使用人工分数、等级或维度进度条。
- R1、R2、R3 等回答引用证据继续保留。
- “专家精选”仍然只表示部分文献是精选资料，与回答评估无关。
- LLM 评估是独立子区域，不与人工二分类结果混为一体。

## 3. 页面整体结构

右侧仍沿用当前“证据与评估”侧栏位置，形成从上到下的三段结构：

1. 顶部标题与关闭按钮。
2. 引用证据区：展示 R1–R3 文献来源，可点击定位对应引用。
3. 评审工作台：使用“人工评估 / LLM 评估”页签切换。

引用证据区保持紧凑，评审工作台作为主要操作区域。侧栏在桌面端固定展示；较窄屏幕继续采用现有抽屉/堆叠方式，不改变当前问答页的总体响应式规则。

## 4. 人工评估

### 4.1 默认状态

- 页签名称：`人工评估`。
- 首要问题：`这条回答是否准确？`
- 两个同级选择按钮：`准确`、`不准确`。
- 未选择前不显示错误原因，减少视觉负担。

### 4.2 选择“准确”

- 高亮“准确”按钮。
- 展示选填的评审说明输入框。
- 提交按钮文案：`保存人工评估`。
- 不要求选择回答片段或错误类型。

### 4.3 选择“不准确”

选择后展开诊断区域，包含：

- `问题片段`：用户可在左侧回答正文中框选文字，系统自动带入；也允许不框选直接提交。
- `错误类型`：支持多选，初始提供检索失败、知识缺失、推理错误、证据不足、无依据断言、回答不完整、领域不匹配。
- `评审说明`：选填文本，用于补充错误原因或修改建议。
- 提交按钮文案：`保存人工评估`。

问题片段是定位辅助信息，不作为提交的强制条件；这样既支持精细标注，也不会阻碍快速评审。

### 4.4 回答框选联动

- 只有存在完整模型回答时才允许框选。
- 用户在回答正文中选择文字后，问答区域发出选择事件，右侧人工评估自动填入文本。
- 再次框选时替换当前未保存片段。
- 用户可以在评审工作台中移除片段。
- 引用编号按钮原有的证据定位行为保持不变。

### 4.5 保存反馈

- 保存过程中按钮进入加载状态并禁止重复提交。
- 成功后显示轻量成功提示，并在当前会话保留已保存内容。
- 失败后保留用户已经填写的信息，显示失败提示并允许重试。
- 当前阶段若后端接口尚未确定，前端使用本地模拟保存，同时通过独立服务函数预留正式接口接入点。

## 5. LLM 评估

### 5.1 初始状态

- 页签名称：`LLM 评估`。
- 显示评估模型/版本信息和 `开始 LLM 评估` 按钮。
- 未运行时不展示虚构评分结果。

### 5.2 运行状态

- 按钮显示加载状态并禁止重复触发。
- 提示正在检查回答与引用证据的一致性、完整性和风险点。

### 5.3 结果状态

采用 ASC 自己的结果卡片，而不是复制参考图：

- 总体结论卡：展示评估摘要和总体可信程度/后端返回的总体结果。
- 维度结果：展示后端实际返回的评价维度；前端不写死旧版 9.1/8.9 分数。
- 风险与修改建议：以短列表展示可执行建议。
- 评估来源：展示所用 LLM、版本及评估时间。
- 保存按钮：`保存 LLM 评估结果`。

若后端暂未提供字段，使用明确标注为“演示数据”的前端样例，不把样例值伪装成真实评估。

## 6. 视觉设计

- 延续 ASC 当前深蓝、浅蓝和白色体系，使用少量绿色表示“准确”，橙红色表示“不准确”及风险。
- 评审结果按钮是人工页签的第一视觉重点。
- 引用证据采用紧凑卡片或胶囊编号，避免占用过多纵向空间。
- 展开诊断区域使用分组标题、留白和浅色背景，不使用密集表格线。
- LLM 结果采用模块化卡片，突出结论、风险和建议，而非大面积仪表盘装饰。
- 保证长文本自动换行，侧栏内部可滚动，底部操作按钮始终容易找到。

## 7. 前端组件与状态建议

建议将现有区域拆分为：

- `EvidencePanel.vue`：右侧容器、引用证据和页签切换。
- `ManualEvaluationPanel.vue`：人工二分类、框选片段、错误类型、说明和保存状态。
- `LlmEvaluationPanel.vue`：LLM 评估触发、加载、结果、错误和保存状态。
- `answerEvaluationModel.js`：演示数据、标签配置和状态结构。
- `answerEvaluation.js`（API/服务层）：人工保存、LLM 评估和 LLM 结果保存的预留调用。

人工评估状态至少包含：

- `verdict`: `accurate | inaccurate | null`
- `selectedExcerpt`: string
- `issueTypes`: string[]
- `comment`: string
- `saveStatus`: `idle | saving | success | error`

LLM 评估状态至少包含：

- `runStatus`: `idle | loading | success | error`
- `model`、`version`、`evaluatedAt`
- `summary`、`dimensions`、`risks`、`suggestions`
- `saveStatus`

## 8. 边界与错误处理

- 没有模型回答时，评估页签显示空状态，不允许提交。
- 没有引用来源时，证据区显示“本次回答暂无引用证据”，人工评估仍可使用。
- LLM 请求失败时显示原因和“重新评估”按钮，不清空人工评估内容。
- 切换页签不丢失任一页签中尚未保存的内容。
- 切换会话时按会话 ID 隔离评估状态，避免串数据。

## 9. 可访问性与交互细节

- 页签、二分类按钮、标签和保存按钮均可通过键盘操作。
- 选中状态不能只依赖颜色，同时使用图标、边框或文字标记。
- 加载状态提供明确文字，失败提示可被辅助技术读取。
- 按钮禁用、聚焦和悬停状态与现有 ASC 页面保持一致。

## 10. 验收标准

- 右侧保留 R1–R3 引用证据及其定位交互。
- 旧版专家分数、维度进度条和静态摘录全部移除。
- 人工评估仅出现“准确 / 不准确”两种最终结果。
- 选择“不准确”后可选择回答片段、多选错误类型并填写说明。
- 选择“准确”可不填写附加内容直接保存。
- 人工与 LLM 页签切换时内容不丢失。
- LLM 评估包含空闲、加载、成功和失败状态。
- 桌面端与现有右侧栏融合，窄屏下无横向溢出且可完整操作。
- 自动测试覆盖二分类切换、诊断区域展开、片段传递、页签保留状态、保存失败重试和 LLM 请求状态。
- 项目现有测试与生产构建通过。

## 11. 本次不做

- 不定义后端数据库表结构。
- 不决定最终使用哪个 LLM Judge 模型或实际评分算法。
- 不对文献本身增加专家分数。
- 不修改知识图谱、文献管理或其他页面的业务逻辑。
