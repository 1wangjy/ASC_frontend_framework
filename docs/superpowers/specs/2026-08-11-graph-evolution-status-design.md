# 图谱演化状态设计

## 目标

将用户看到的“图谱构建”统一调整为“图谱演化”，并明确区分 Professional Graph 构建完成与模拟结束后的最终图谱演化完成。仅修改前端，不修改 5002 后端。

## 状态来源

- 图谱构建状态与构建百分比继续使用 `/api/graph/project/list` 和图谱任务状态接口的真实返回值。
- 模拟状态使用 `/api/simulation/history` 的 `project_id`、`simulation_id`、`runner_status`、`current_round` 和 `total_rounds`。
- 同一项目存在多条历史记录时，采用时间最新且包含 `simulation_id` 的分析记录。
- 不把三个阶段虚构为固定的 33%/66%/100%。

## 显示规则

| 后端真实状态 | 项目卡和任务弹窗文案 | 百分比 |
|---|---|---|
| 图谱仍在构建 | 沿用当前图谱构建文案 | 图谱任务真实进度 |
| Professional Graph 完成、尚未模拟 | 知识图谱专业构建完成 | 图谱任务真实进度 |
| 模拟已创建但未运行 | 等待知识图谱演化 | 0% |
| 模拟运行中 | 知识图谱演化中 | `current_round / total_rounds`，最高 99% |
| 模拟正常完成 | 知识图谱演化完成 | 100% |
| 模拟失败或手动停止 | 知识图谱演化失败 / 已停止 | 保留最后真实轮次进度，不标记完成 |

侧边栏入口改为“图谱演化”。项目面板标题改为“知识图谱演化项目”，全局浮层改为“图谱演化任务”。

## 容错与边界

- 模拟历史请求失败时，项目列表仍正常显示，并回退到图谱构建状态；不能因辅助状态接口失败而显示“无法连接后端”。
- `runner_status === 'completed'` 才能判定演化完成；`stopped` 不算完成。
- 不改变图谱构建、模拟或报告接口，不触发任何新的 POST。

## 验证

- 纯模型测试覆盖无模拟、等待、运行、完成、失败、停止和多条历史选择。
- 监控器测试覆盖模拟历史合并和历史接口失败回退。
- 组件渲染测试覆盖三个统一名称。
- 运行全量测试与生产构建。
