# 新版前端与现有后端 API 对接设计

## 目标

在不改动后端实现和数据库结构的前提下，让新版前端通过现有 Flask API 读取、提交和展示真实数据，并形成一份可交接的逐接口契约表。页面不得在后端为空或失败时静默回退到 Mock 数据，以免把演示内容误认为真实结果。

## 范围

本次覆盖以下工作：

- 校对 `frontend/src/api/*.js` 中每个请求的方法、URL、参数位置和后端 Flask 路由。
- 将报告状态查询改为 `POST /api/report/generate/status`，请求体接收 `task_id` 或 `simulation_id`。
- 将新版文献管理页接入 PDF Library 的查询、上传、预览、下载和删除接口。
- 将新版知识图谱工作区接入项目列表与图谱数据接口。
- 将新版问答页接入项目选择、CoD GraphRAG 查询、LLM 评价和反馈接口。
- 为加载、空数据、无可用图谱、请求失败和重试提供明确页面状态。
- 生成 `docs/frontend-backend-api-contract.md`，逐项记录请求方法、URL、前端函数、页面功能、后端实现位置、状态和限制。

本次不覆盖：

- 不实现或伪造 `POST /api/graph/launch`；契约表将其标记为后端待实现。
- 不修改后端 `/api/report/generate/status` 的路由实现。
- 不新增后端接口、数据库表、鉴权方式或任务系统。
- 不把 `/data` 和 `/models` 的说明页面虚构成真实业务页面，因为后端没有对应的专用接口契约。
- 不恢复旧版路由作为新版页面的替代品。

## 方案选择

采用“真实数据优先、页面适配器隔离”的方案。API 文件只负责 HTTP 请求；独立的纯函数适配器负责把后端响应转换成新版组件使用的数据结构；视图负责加载、选择、提交、重试和空状态。

未采用 Mock 回退方案，因为它会让接口断开时仍显示看似正常的研究结果。未采用恢复旧页面方案，因为目标是验证和完成新版页面的数据链路。

## 架构与数据流

### 统一 API 层

`src/api/index.js` 继续作为唯一 Axios 客户端，保留 `X-NEXUS-USER`、超时、错误提取和重试策略。业务组件不得创建新的 Axios 实例。

`src/api/graph.js` 增加项目列表封装，继续提供图谱数据和 GraphRAG 调用。`src/api/report.js` 修正报告状态请求契约。PDF 与 simulation API 保持现有路径，测试负责防止方法或 URL 漂移。

### 项目与图谱上下文

新增一个纯函数模型，用于：

- 从项目列表中筛选拥有 `graph_id` 的项目；
- 恢复本机最近选择的项目；
- 当选择无效时回退到最近更新且拥有图谱的项目；
- 只在 `localStorage` 保存项目 ID，不缓存项目或图谱响应。

知识图谱工作区提供项目选择控件。问答页复用同一个项目 ID；如果没有可用图谱，问题提交按钮保持不可用并解释原因。后端请求始终显式发送 `project_id` 和 `graph_id`，不启用 `allow_latest_fallback`。

### 图谱响应适配

新增纯函数把后端图谱数据转换为画布节点和边：

- 节点 ID 兼容 `node_id`、`uuid`、`id`；名称兼容 `name_zh`、`display_name`、`name`；类型兼容顶层与 `attributes.entity_type`。
- 别名、证据数量和关系数量缺失时使用安全默认值。
- 边端点兼容字符串 ID 与嵌套端点对象；引用不存在节点的边会被过滤。
- 后端没有坐标时使用确定性布局生成坐标，保证同一数据刷新后位置稳定。

页面切换项目时重新请求图谱并重置聚焦状态。空节点数组显示“图谱暂无节点”，而不是静态示例图。

### 问答响应适配

问答提交调用 `POST /api/graphrag/cod-query`，请求包含问题、选中的 `project_id`、`graph_id` 和当前推理模式。响应适配器使用：

- `final_answer` 生成摘要和正文段落；
- `references` 生成证据卡片；
- `citation_bindings` 将引用关联到回答片段；
- `debug_trace.stages` 或已有路径字段生成简短研究路径；
- `qa_run_id` 保留给后续人工反馈。

回答进行中显示真实加载状态。失败时保留用户问题并显示可重试错误，不调用 `completeMockAnswer`。人工反馈和 LLM Judge 使用真实回答上下文，并在评价 API 未启用时明确显示不可用状态，不伪造成功结果。

### 文献响应适配

PDF Library 返回的是文件元数据，不包含 DOI、作者、期刊等学术元数据。适配器按以下规则展示：

- `file_id` -> `id`
- `filename` -> `title`
- `description` -> `abstract`
- `category` -> 类型标签和标签
- `created_at` -> 年份与创建时间
- `file_size`、`sha256` 作为文件信息

后端未提供的 DOI、作者、期刊、引用次数显示为空值或“不适用”，不得生成假数据。上传模式提交真实 `File[]`；上传成功后重新加载列表。预览、下载和删除调用已有接口。DOI 与 BibTeX/CSV 导入入口显示“当前后端未提供接口”，不再触发模拟成功。

## 报告状态契约

前端函数改为接收对象：

```js
getReportStatus({ taskId, simulationId })
```

它发送：

```http
POST /api/report/generate/status
Content-Type: application/json
```

请求体只包含非空字段：

```json
{
  "task_id": "task_xxx",
  "simulation_id": "sim_xxx"
}
```

该函数不再接受 `reportId`，因为后端状态接口不读取 `report_id`。

## 错误与空状态

- 后端不可达：显示后端连接失败并提供重试。
- 接口 400/404/500：展示 Axios 统一提取的后端错误，不替换为 Mock。
- 项目列表为空：图谱和问答显示“暂无可用图谱项目”。
- PDF 列表为空：显示真实空文献库与上传入口。
- 图谱节点为空：保留项目选择，显示图谱为空。
- 上传部分成功：展示成功数量与失败文件原因，然后刷新列表。
- `POST /api/graph/launch` 返回 404：保持当前入口错误状态，并在接口契约表标注后端待实现。

## 测试设计

所有生产代码遵循测试先行：

- API 契约测试校验每个前端函数的方法、URL和参数位置。
- 项目选择模型测试有效恢复、无效回退和无图谱空状态。
- 图谱适配器测试多种节点/边字段、悬空边过滤和稳定坐标。
- 问答适配器测试回答、引用、空回答与错误响应。
- 文献适配器测试缺失学术元数据时不生成假值。
- 页面源代码测试确保新版视图使用真实 API，且不再调用对应 Mock 完成函数。
- 完成后运行全部 Node 测试和 `npm run build`。

测试不得调用真实 LLM、Zep 或具有副作用的上传/删除接口。真实后端只用于只读烟雾验证：健康检查、项目列表和 PDF 列表。

## 交付物与完成标准

- 新版文献管理、知识图谱工作区和问答首页使用真实 API 数据流。
- 报告状态方法、URL 和参数与后端一致。
- `/api/graph/launch` 明确保留为唯一已知后端缺失接口。
- 当前已有的其他前端 API 封装与后端路由的方法和路径一致。
- 所有新增及现有前端测试通过，生产构建成功。
- `docs/frontend-backend-api-contract.md` 覆盖所有前端 API，至少包含：模块、前端函数、HTTP 方法、URL、页面功能、后端文件/路由、完成状态、调用页面和限制说明。
