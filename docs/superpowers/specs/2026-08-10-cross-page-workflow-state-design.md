# 侧边栏切换时保留页面任务状态设计

## 目标

用户通过侧边栏在问答首页、文献管理和图谱构建之间切换时，正在执行的问答请求和图谱构建页面状态不得因为路由切换而丢失。返回原页面后，界面应继续显示真实的生成中状态，或显示离开期间已经完成的结果。

本功能只覆盖当前网站会话中的前端路由切换，不承诺浏览器刷新、关闭标签页或重新访问 URL 后恢复尚未完成的问答请求。

## 已确认的产品规则

- 同一时间只允许一个问答生成请求。
- 切换页面时不增加全局问答状态按钮、弹窗或完成提醒。
- 返回问答首页时直接呈现原来的问题、设置、生成状态和结果。
- 图谱构建页返回后保留当前项目、步骤、日志、上传选择和构建状态。
- 关闭或刷新网站后，前端内存任务可以结束；已经写入后端的数据仍通过现有接口重新加载。
- 删除图谱流程顶部重复的“去图谱问答”按钮。
- 保留左侧项目卡片的“去问答”，因为它明确绑定一个图谱项目。
- 保留侧边栏“问答首页”，作为通用问答入口。

## 当前问题

`AscQaView` 的问答状态和等待中的请求保存在页面组件内部。普通路由切换会卸载组件，随后即使请求返回，原组件也已不再可见，用户返回时会得到一个新的问答页面实例。

图谱构建已有全局任务轮询器，可以从后端项目列表和任务状态接口重新同步概要进度；但图谱工作台内部的当前步骤、日志及临时选择仍属于页面组件状态，路由卸载后会丢失。

## 方案选择

采用 Vue `KeepAlive` 对指定路由页面做会话内缓存，不建立新的全局问答任务仓库，也不把进行中的问答写入浏览器存储。

选择该方案的原因：

- 与“切走后继续、回来原样”的产品行为完全一致。
- 当前问答请求无需重写为新的任务协议。
- 不增加后端接口依赖。
- 不增加新的全局状态提示或复杂任务管理界面。
- 保留现有页面内状态和 Promise 回调，改动范围较小。

不采用的方案：

- 全局问答任务仓库：可以脱离页面管理请求，但当前只有一个问答任务，复杂度没有必要。
- `localStorage` 或 `sessionStorage`：可以保存文本快照，但不能保存正在等待的 HTTP 请求，也无法在刷新后重新取得未持久化的后端回答。

## 路由缓存设计

在应用根路由出口使用 `RouterView` 插槽和 `KeepAlive`。

仅缓存两个页面组件：

1. `AscQaView`
2. `GraphProjectWorkspaceView`

文献管理、模拟、报告和深度互动页面仍按现有方式创建与卸载，避免无边界缓存所有大型页面。

缓存页面使用稳定的路由名称作为缓存键：

- 问答首页始终只有一个缓存实例。
- 图谱构建页始终只有一个缓存实例；在不同项目参数之间切换时更新当前项目，不为每个项目永久保留独立页面副本。

组件名称应显式、稳定，避免生产构建后 `KeepAlive` 的 `include` 过滤失效。

## 问答数据流

1. 用户在问答首页提交问题。
2. `AscQaView` 进入生成中状态并发送现有问答请求。
3. 用户通过侧边栏进入其他页面。
4. `AscQaView` 被停用但不卸载，请求和页面内响应式状态继续存在。
5. 请求在用户离开期间返回时，仍更新被缓存的页面状态。
6. 用户返回问答首页：
   - 请求尚未完成时继续显示生成中；
   - 请求已完成时直接显示真实回答；
   - 请求失败时显示原有失败与重试状态。

问答页不得因为 `deactivated` 生命周期自动取消请求或重置对话。用户点击“新建问答”时仍按现有逻辑主动清空状态。

## 图谱构建数据流

1. 用户在图谱构建页选择项目并启动后端工作流。
2. 用户切换到其他侧边栏页面。
3. 图谱工作台组件保留当前项目、阶段、日志和页面内轮询状态。
4. 全局图谱任务监控继续按照现有后端任务接口同步项目概要状态。
5. 用户返回图谱构建页后看到同一个工作台实例及最新状态。

如果用户在图谱构建路由内切换到另一个项目，仍执行现有的项目切换和数据加载逻辑，不能把前一个项目的图谱、日志或临时文件显示到新项目。

## 重复问答入口

删除 `MainView` 顶部黑色“去图谱问答”按钮及只为该按钮服务的显示判断。

保留：

- 左侧项目列表中的“去问答”：进入该项目对应的问答范围。
- 侧边栏“问答首页”：进入通用问答页面。
- 图谱构建步骤内部在最终 Professional 图谱完成后的问答入口：用于流程完成后的明确下一步操作。

## 刷新与关闭边界

刷新页面会销毁浏览器中的 JavaScript 上下文、Vue 组件实例和进行中的前端请求等待状态。

- 已上传并保存的文献：由后端重新查询。
- 已创建的图谱项目和图谱任务：由现有项目列表、任务状态接口重新查询。
- 已完成并由后端保存的图谱数据：由现有图谱接口重新查询。
- 正在等待的问答：当前没有问答任务 ID、状态查询和历史结果接口，刷新后无法可靠恢复。

未来若后端提供异步问答任务与历史接口，可以再扩展为刷新后恢复；本次不预留虚假进度或本地模拟结果。

## 错误处理

- 路由切换本身不得修改问答请求版本、问答状态或草稿。
- 缓存页面重新激活时，不重复发送正在执行或已经完成的问答。
- 图谱页面重新激活时不得创建第二套相同轮询器。
- 项目失效、后端断线及问答失败继续使用现有页面错误状态。
- 页面缓存不能绕过现有 Professional 图谱完成后才能问答的范围校验。

## 验证要求

- 问答提交后切换到文献管理，再返回问答首页，请求只能发送一次。
- 返回时生成中状态仍存在；受控请求完成后显示同一问题的回答。
- 问答完成后切换页面再返回，答案和评估状态不丢失。
- 图谱构建过程中切换到其他页面再返回，项目、阶段和日志不重置。
- 图谱构建路由内部切换项目时不会串用上一个项目的数据。
- 顶部黑色“去图谱问答”不再渲染，项目卡片入口仍可用。
- 全量自动化测试和生产构建通过。
- 浏览器真实路由切换烟测通过，且不发送额外的问答或图谱创建请求。
