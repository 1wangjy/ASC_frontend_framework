# 数据平台文献表单弹窗设计

## 目标

优化“数据平台 → 文献库管理”的手动新增/编辑文献表单，使全部字段在常见桌面和笔记本屏幕上清晰可达，同时保持现有保存、编辑和附件关联逻辑不变。

## 业务关系

- 表单保存的是 SQLite `literature` 记录中的文献元数据。
- 保存成功后，列表生成对应文献卡片，并显示该记录的元数据。
- 新记录可以暂时没有附件；用户随后通过文献卡片上传附件，附件以 `litId` 与该记录关联。
- 后续上传附件不覆盖手动填写的文献元数据。

## 布局

- 弹窗桌面宽度约 880px，最大高度不超过视口。
- 标题栏和底部操作栏保持可见，表单正文在内容过多时独立滚动。
- 桌面使用双列网格，窄屏自动改为单列。
- 标题、作者、期刊/会议、摘要、备注占整行。
- 类型与年份、卷与期、页码与 DOI 分别并排。
- 标签使用“卷（Volume）”“期（Number）”“页码（Pages）”“备注（Note）”。
- 标题和作者显示必填标记。
- 标题下增加说明：“保存后可在文献卡片中上传附件。”

## 交互与边界

- 保留遮罩点击关闭、取消、保存/更新行为。
- 不改变 `addLitForm` 字段、校验、payload、3001 API、附件 API 或列表卡片。
- 不修改其他数据管理弹窗，不新增依赖。

## 验证

- 聚焦测试确认全部文献字段、说明文案、必填标记和操作按钮完整呈现。
- 前端 build 通过。
- 浏览器验证桌面双栏、内部滚动、固定操作区及窄屏单栏，没有字段或按钮被视口裁切。
