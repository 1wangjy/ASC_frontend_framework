# 报告生成中心数据接入设计

## 目标

把当前只有空状态的“报告生成”页面接入后端已经存在的报告存储与查询能力。报告由后端生成和保存，前端不复制报告正文、不伪造 `report_id`，只负责列出、关联和打开真实报告。

## 已确认的后端能力

- `POST /api/report/generate`：启动唯一报告生成，返回 `report_id` 和 `task_id`。
- `GET /api/report/list?limit=50`：列出后端已经保存的报告。
- `GET /api/report/<report_id>`：读取报告详情。
- `GET /api/report/by-simulation/<simulation_id>`：按模拟查询报告。
- `GET /api/report/check/<simulation_id>`：查询报告状态及深度互动是否解锁。
- 报告内容由后端保存为元信息、完整 Markdown 和分章节文件。

## 页面行为

`/reports` 作为报告中心，首次进入即请求真实报告列表：

1. 加载中显示轻量加载状态。
2. 无报告时保留“尚无报告，请先完成图谱演化”的空状态。
3. 有报告时按创建时间倒序显示报告卡片。
4. 卡片展示报告标题、生成状态、创建时间和完成时间；能够关联时同时展示图谱项目名称。
5. 点击卡片进入 `/report/:reportId`，复用现有报告详情与生成进度页面。
6. 报告仍在生成时允许进入详情继续查看进度；报告失败时展示失败状态，不自动重新生成。
7. 页面刷新后重新从后端加载，不依赖内存或 `localStorage` 保存报告正文。

## 图谱项目关联

报告列表记录包含 `simulation_id` 和 `graph_id`，但不直接包含项目名称。前端复用已有图谱项目列表，并按项目的 `simulation_id` 或 `graph_id` 进行关联：

- 匹配成功：显示真实项目名称。
- 匹配失败：显示报告标题，不伪造项目名称，也不隐藏报告。

该关联仅用于展示，不改变后端报告数据。

## 单图谱单报告约束

- 报告中心只查询和打开报告，不提供“重新生成”按钮。
- 现有生成请求继续固定 `force_regenerate: false`。
- 同一 `simulation_id` 若出现重复记录，前端按后端返回的最新有效报告展示一条，并保留真实 `report_id`。
- 报告中心不得发起 `/api/report/generate` 请求。

## 组件与接口边界

- `src/api/report.js`：新增只读的 `listReports` 请求封装。
- `src/features/reports/reportCenterModel.js`：负责规范化、排序、去重和项目名称关联，保持为可独立测试的纯函数。
- `src/views/ReportCenterView.vue`：负责加载状态、错误状态、空状态和报告卡片渲染。
- `src/views/ReportView.vue`：保持现有职责，不复制报告详情实现。

## 错误处理

- 列表请求失败时显示“报告列表加载失败”和重试按钮，不把失败误报为“尚无报告”。
- 单条报告字段缺失时使用安全回退文本，其他有效报告仍可展示。
- 项目列表暂时不可用时仍展示报告，项目名显示“未关联项目”。
- 所有列表操作都是 GET，不触发报告生成、删除或覆盖。

## 验收标准

1. `/reports` 会调用一次 `GET /api/report/list` 并展示真实返回结果。
2. 报告卡片点击后进入对应 `/report/:reportId`。
3. 已完成、生成中、失败三类状态显示清楚。
4. 有真实项目匹配时显示项目名称；匹配失败不影响报告查看。
5. 刷新 `/reports` 后报告能够从后端重新出现。
6. 同一模拟最多显示一个报告，且不提供重新生成入口。
7. 空列表、接口失败和字段缺失都有明确且不同的界面状态。
8. 实现不修改后端，不发起任何新的报告生成请求。
