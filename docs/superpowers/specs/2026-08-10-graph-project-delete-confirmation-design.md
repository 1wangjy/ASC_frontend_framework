# 图谱项目删除确认层设计

## 问题

图谱项目工作区使用浏览器原生 `confirm` 确认删除。在部分嵌入式浏览器环境中，该原生方法会抛出 `Illegal invocation`，导致删除请求尚未发送便终止。后端现有两个删除接口及 Vite 代理均可正常响应。

## 设计

- 使用 Vue 页面内确认层替代原生 `confirm`。
- 用户点击“删除”时只记录待删除项目并显示确认层，不立即调用接口。
- 取消操作关闭确认层且不发送请求。
- 确认操作沿用现有 `deleteGraphProjectResources`：有 `graph_id` 时先删除远端图谱，再删除本地项目；没有 `graph_id` 时直接删除项目。
- 构建中项目继续显示更强的不可撤销提示。
- 删除中禁止重复提交；成功后清理当前选择并刷新项目列表；失败时保留现有错误提示。

## 范围

- 只修改前端组件和对应自动化测试。
- 不修改后端代码、接口路径、请求结构或删除顺序。
- 不增加重命名、批量删除或撤销功能。

## 验证

- 自动化测试覆盖确认层显示、取消不删除、确认后调用删除流程以及构建中项目警告。
- 运行相关测试、完整测试和生产构建。
