# 模拟流程准确恢复设计

## 目标

用户离开图谱演化页面去问答、报告或文献页面后，返回任一图谱项目时，应打开该项目后端最新模拟记录对应的准确阶段，并展示后端已经运行到的最新 Stage；页面返回不得重新启动模拟。

## 边界

- 只修改 3000 前端，不修改 5002 后端和 3001 前端。
- 后端 `simulation/history`、`run-status` 和 `run-status/detail` 是状态事实源。
- 前端 KeepAlive 与内存路由只用于快速恢复，不能覆盖更新的后端状态。
- 不删除已经产生的重复 simulation 数据，不触发真实构建、模拟或报告写请求。

## 方案

1. 根据项目监控记录中的最新 `simulationId` 与 `evolutionStatus` 计算恢复路由：环境准备阶段进入 `Simulation`，已运行、完成、停止或失败进入 `SimulationRun`；没有模拟记录才进入 `Process`。
2. 项目表和浮动任务入口都先采用上述后端派生路由，内存路由仅作为无后端模拟记录时的次级恢复信息。
3. `Step3Simulation` 挂载后先读取 `run-status` 和详情：运行中继续轮询，完成/停止/失败恢复终态；仅后端明确返回未启动状态时执行首次启动。
4. 移除自动启动请求中的 `force: true`，防止重新挂载清空并重启已有流程。

## 验证

- 单元测试覆盖项目恢复路由和已有运行状态恢复。
- 回归测试证明重新挂载不会调用启动接口。
- 运行相关测试与一次生产构建。
