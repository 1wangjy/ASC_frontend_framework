# 智能问答页：真实请求与界面预览双通道设计

日期：2026-08-05

## 1. 目标与边界

在不修改现有页面外观、不修改后端代码的前提下，让智能问答页尽可能使用现有后端能力，并在本地暂时没有可用图谱时仍能查看完整回答界面。

本阶段只处理智能问答页。文献管理、知识图谱、模型分析和数据页面在本阶段验证完成后再依次处理。

## 2. 已确认事实

- 当前 `GET /api/graph/project/list` 成功返回，但 `data` 是空数组，因此前端无法自动取得 `project_id` 或 `graph_id`。
- `POST /api/graphrag/cod-query` 必须收到 `question`，并需要 `project_id`、`graph_id` 或 `simulation_id` 中至少一个上下文标识。
- 问题和回答模板不是接口启动条件；当前阻塞原因仅是没有可发现的图谱上下文。
- 后端已有真实问答、LLM Judge、专家反馈等接口，不需要在前端重新实现这些后端能力。

## 3. 总体方案

页面保留现有布局，增加互相隔离的两条使用路径。

### 3.1 真实问答路径

页面启动时按以下优先级寻找图谱：

1. 从 `/api/graph/project/list` 返回的已完成项目中选择带 `graph_id` 的项目；
2. 如果项目列表没有可用图谱，则读取本地前端环境变量 `VITE_DEFAULT_GRAPH_ID`，并可同时读取 `VITE_DEFAULT_PROJECT_ID`；
3. 两者都不存在时，不发起真实 CoD 请求。

真实问答使用现有 `POST /api/graphrag/cod-query`。真实回答才允许继续调用 Judge 和专家反馈接口。项目列表获得的真实图谱优先于环境变量，避免以后后端数据恢复后仍误用旧配置。

不启用 `allow_latest_fallback`，避免问题被静默发送到错误图谱。

### 3.2 界面预览路径

没有可用图谱时，当前提示区域增加“预览回答页面”入口。入口展示已有的固定问题、回答结构、证据引用和推理过程，用于直观看到下一页外观。

预览回答必须满足：

- 页面醒目标注“界面预览数据，未请求后端”；
- 不生成虚假的 `qa_run_id`、`report_id` 或其他后端 ID；
- Judge、专家反馈和任何写入后端的操作不可用，并说明需先完成真实问答；
- 刷新或退出预览不会影响后端数据；
- 支持 `/?preview=answer` 直接打开同一预览，便于本地检查页面。

预览是页面展示工具，不是功能完成状态，也不冒充大模型回答。

## 4. 页面状态

问答页使用四类明确状态：

| 状态 | 页面表现 | 允许操作 |
| --- | --- | --- |
| 正在寻找图谱 | 保持加载提示 | 暂不提交 |
| 真实图谱可用 | 显示当前项目并启用输入框 | CoD 问答、Judge、反馈 |
| 无可用图谱 | 显示原因和预览入口 | 仅界面预览 |
| 预览回答 | 展示完整回答页及预览标识 | 查看回答结构，不写后端 |

真实接口失败时保留用户问题，显示后端错误并允许重试；不自动切换成演示答案，以免掩盖真实错误。

## 5. ID 的处理原则

用户不需要在页面中理解或手动填写 `project_id`、`graph_id`、`simulation_id`。这些 ID 是前后端关联资源用的内部标识：

- `project_id`：一个建图项目；
- `graph_id`：项目完成后生成的知识图谱；
- `simulation_id`：基于图谱创建的分析工作台；
- `task_id`：异步任务进度查询凭证；
- `report_id`：已生成报告的标识。

前端应从上一步接口响应中保存并传递这些 ID。临时的 `VITE_DEFAULT_GRAPH_ID` 只用于本地联调，由后端同学提供一次即可，不放到普通用户界面。

## 6. 数据与组件改动

- 项目上下文模型增加“后端项目列表 + 环境变量回退”的纯函数，便于独立测试。
- 问答状态增加 `answerSource: 'live' | 'preview'`，回答组件据此显示来源并控制评价功能。
- 无图谱提示增加显式预览按钮。
- 路由查询参数只负责触发预览，不改变正常首页行为。
- 现有样式、页面结构、模型/框架/推理选择器位置保持不变。

## 7. 测试与验收

至少覆盖：

1. 项目列表有 `graph_id` 时优先选择真实项目；
2. 项目列表为空、环境变量有 `graph_id` 时可发起真实请求；
3. 两者都没有时不发送 CoD 请求；
4. 点击预览或访问 `/?preview=answer` 能展示完整回答页；
5. 预览页始终标注数据来源，且不调用 Judge/反馈接口；
6. 真实回答仍能展示引用、证据、Judge 和反馈；
7. 单元测试与生产构建通过。

## 8. 明确限制

前端无法凭空创建真实 `graph_id`。若要得到真实大模型回答，必须满足以下任一条件：后端项目列表返回一个已完成图谱，或本地环境中配置后端同学提供的真实 `graph_id`。本设计保证在条件满足后无需再次修改页面代码即可切换到真实流程。
