# 报告生成独立导航设计

## 目标

把现有五步工作流按用户操作边界拆成三个前端模块，同时继续复用当前后端接口：

1. **图谱演化**：图谱构建、环境搭建、开始模拟；模拟正常结束即完成图谱演化。
2. **报告生成**：承接模拟结束后的单一报告生成、进度恢复与报告查看。
3. **问答首页**：后续承接报告完成后的深度互动；本次不迁移深度互动实现。

## 已确认行为

- 主侧边栏新增“报告生成”，顺序位于“图谱演化”之后。
- `/reports` 是报告生成模块入口。
- 没有可恢复的 `report_id` 时，入口显示“尚无报告，请先完成图谱演化”的空状态，不发起报告生成请求。
- 现有 `/report/:reportId` 继续承载真实报告生成与查看页面，但导航归属从“图谱演化”改为“报告生成”。
- 用户访问过某个报告后，再点击“报告生成”应恢复该报告路由；尚未访问报告时进入 `/reports`。
- Step 3 模拟完成后的“生成/查看报告”继续复用现有单报告流程和后端返回的 `report_id`，成功后进入 `/report/:reportId`。
- `/report/:reportId` 不显示图谱项目管理侧栏；图谱项目管理只保留在图谱演化模块。
- 图谱演化的路由范围仅包含 `/process`、`/simulation/:simulationId` 和 `/simulation/:simulationId/start`。
- 本次不修改后端、不伪造 `report_id`、不增加报告列表接口、不迁移深度互动代码。

## 路由与导航

| 路由 | 侧边栏归属 | 页面作用 |
| --- | --- | --- |
| `/process/:projectId?` | 图谱演化 | 图谱构建与项目管理 |
| `/simulation/:simulationId` | 图谱演化 | 环境搭建 |
| `/simulation/:simulationId/start` | 图谱演化 | 模拟与图谱演化 |
| `/reports` | 报告生成 | 无报告时的空状态入口 |
| `/report/:reportId` | 报告生成 | 单一报告生成进度与报告查看 |
| `/interaction/:reportId` | 暂保持现状 | 下一阶段迁移到问答首页 |

导航状态分别记忆最近一次图谱演化路由和最近一次报告路由，二者不能互相覆盖。刷新页面后，后端已有的报告仍由现有 `getReport(reportId)` 等接口重新加载；页面切换期间继续由现有 KeepAlive 机制保存正在运行的报告页面实例。

## 组件边界

- 新增轻量 `ReportCenterView`，只负责 `/reports` 的空状态，不拥有报告生成逻辑。
- `ReportView`、`Step4Report` 和 `singleReportModel` 保持现有真实后端流程。
- `AscShell` 仅在图谱演化路由显示 `GraphProjectWorkspacePanel`。
- `appNavigation` 分别维护图谱演化和报告生成的最近路由。
- `Step3Simulation` 保持现有“已有报告则复用、没有则只生成一次”的行为。

## 错误与边界处理

- 未取得 `report_id` 时不能跳入 `ReportView`，也不能在前端生成假 ID。
- 报告生成失败继续由现有报告页展示错误，不自动重试非幂等生成请求。
- 直接访问无效 `/report/:reportId` 时保留现有后端错误处理；不回退到其他报告。
- 本次不提供报告列表，因为当前后端没有明确的报告列表契约。

## 验收标准

1. 侧边栏出现“报告生成”。
2. `/reports` 显示确认过的空状态且不发 POST。
3. 进入 `/report/:reportId` 时高亮“报告生成”，不显示图谱项目表。
4. 报告页与其他页面来回切换时，当前报告生成实例保持运行。
5. 再次点击“报告生成”恢复最近报告；无最近报告时进入 `/reports`。
6. 图谱演化导航只恢复图谱、环境或模拟路由，不再恢复报告路由。
7. 现有单报告防重复生成逻辑、全量测试和生产构建保持通过。
