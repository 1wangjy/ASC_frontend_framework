# 多轮对话前端接入设计

## 目标

在当前 ASC 问答首页已经完成的“多轮连续”首屏上接入 Multi-Discussion 后端，使用户能够提交第一轮问题、查看分析进度和回答，并使用同一个会话继续追问。

本阶段只完成 API、轮询、会话状态和回答内容呈现。多轮回答区暂时迁移已有 Multi-Discussion 界面的消息、进度和证据展示，后续再独立进行 UI 设计。

## 不可改变的界面约束

当前 `QuestionComposer.vue` 中的多轮工具栏是既有 UI 合同。本任务不得改变以下内容：

- DOM 排列和控件顺序；
- 控件尺寸、颜色、边框、圆角、间距和字体；
- “+”、模型、推理、多模块回答和发送按钮的图标与视觉样式；
- “单轮深度 / 多轮连续”模式切换的视觉样式；
- 首屏标题、输入区域和推荐问题卡片的布局。

允许改变的只有控件数据来源、事件处理、启用状态和请求行为。模型下拉选项由后端能力接口动态提供真实可用模型，但沿用现有下拉控件样式。

## 页面状态与模式分流

`AscQaView.vue` 继续作为问答页面编排层。

- 单轮模式继续执行现有 CoD GraphRAG 请求和回答展示，不改变接口、状态或样式。
- 多轮模式在首屏仍使用现有 `QuestionComposer.vue`。
- 用户提交第一问后，页面进入多轮会话状态，立即显示用户消息和分析进度。
- 多轮回答区暂时复用已有 `MultiDiscussionPanel.vue` 中的消息、分析进度、Markdown、引用、图片分析和视觉证据展示部分。
- 不迁移旧面板的首屏标题、图谱选择器和输入工具栏。所有轮次继续使用当前 `QuestionComposer.vue` 的按钮区发送。

多轮会话状态至少包含：

- `phase`: `empty`、`running`、`answered` 或 `error`；
- `conversationId`；
- 当前 `requestId`；
- `messages`；
- `analysisProgress`；
- 当前错误；
- 当前上传图片；
- 当前模型、推理和多模块回答设置。

## 组件边界

### `QuestionComposer.vue`

保留模板结构和全部样式，只增加行为：

- “+”选择图片后保存真实 `File` 与预览 URL；
- 模型选择向父组件输出后端 `model_mode`；
- 推理选择继续输出 `Auto`、`CoT` 或 `ToT`；
- 多模块回答选择输出 `inline` 或 `evidence`；
- 多轮发送按钮在请求条件满足时启用并触发提交；
- 组件卸载或移除图片时释放预览 URL。

### `multiDiscussionApi.js`

使用当前项目共享的 Axios 实例和相对 `/api` 路径，统一经过 Vite 的 `/api -> 5000` 代理：

- `POST /api/multi-discussion/chat`；
- `GET /api/multi-discussion/progress/{request_id}`；
- `GET /api/multi-discussion/conversations/{conversation_id}`；
- `GET /api/multi-discussion/capabilities`。

附件和视觉证据 URL 使用当前 `API_BASE_URL` 构造，不硬编码旧项目的 `5001` 地址。

### `multiDiscussionModel.js`

负责纯数据逻辑：

- 创建初始多轮状态；
- 将能力接口的 `model_modes` 转换为现有下拉选项；
- 构造聊天请求；
- 将后端回答和历史消息转换为临时回答组件需要的结构；
- 合并进度快照；
- 固定并校验 `project_id`、`graph_id` 和 `conversation_id`；
- 生成每轮唯一的 `request_id`。

### `multiDiscussionPoller.js`

负责单一轮询生命周期，不直接依赖 Vue 组件：

- 使用串行 `setTimeout`，前一次请求完成后再安排下一次，避免轮询重叠；
- 接受开始、结果、错误和停止回调；
- 通过请求代次或令牌忽略旧轮次返回；
- 提供显式 `start()` 和 `stop()`；
- 页面卸载、切换项目、新建讨论和新轮次开始时均可安全停止。

### 临时多轮回答组件

只迁移已有界面的内容展示能力：

- 用户和助手消息；
- 公开分析阶段和进度；
- Markdown 回答；
- 引用证据；
- 上传图片和图片分析；
- 视觉证据；
- 错误与重试入口。

该组件不拥有首屏、图谱选择器或发送工具栏，避免出现两套输入界面。

## 请求字段映射

每轮请求携带：

| 当前控件或上下文 | 后端字段 | 映射规则 |
| --- | --- | --- |
| 问题输入框 | `question` | 去除首尾空白后的问题文本 |
| 当前项目 | `project_id` | 来自当前已通过问答资格筛选的项目 |
| 当前图谱 | `graph_id` | 来自当前项目，禁止用户消息覆盖 |
| 当前会话 | `conversation_id` | 第一轮省略，后续轮次使用后端返回值 |
| 本轮请求 | `request_id` | 前端每轮生成新的唯一值 |
| 模型下拉 | `model_mode` | 使用能力接口返回的 `mode` |
| 推理下拉 | `options.reasoning_mode` | `Auto -> auto`、`CoT -> cot`、`ToT -> tot` |
| 图片按钮 | `images` | 使用 `multipart/form-data` 上传真实 `File` |
| 正文穿插 | `enable_multimodal_response` | `true` |
| 正文穿插 | `multimodal_render_mode` | `inline` |
| 证据区域 | `enable_multimodal_response` | `true` |
| 证据区域 | `multimodal_render_mode` | `evidence_section` |

无图片时使用 JSON；有图片时使用 `multipart/form-data`。发送条件为“存在问题文本或有效图片、存在有效项目和图谱、当前没有正在提交的轮次”。

## 数据流

### 第一轮

1. 校验当前项目和图谱资格。
2. 生成 `request_id`，把用户消息立即加入消息列表。
3. 进入 `running` 状态并发出聊天 POST 请求。
4. 同时按 `request_id` 启动进度轮询。
5. POST 返回后校验响应的 `project_id` 和 `graph_id`。
6. 保存 `conversation_id`，适配并加入助手回答。
7. 停止轮询并进入 `answered` 状态。

### 后续轮次

后续请求使用同一个 `conversation_id`，但每轮生成新的 `request_id`。后端返回的作用域或会话标识与当前状态不一致时，前端拒绝合并该响应。

### 恢复与新建讨论

- 按 `graph_id` 在浏览器存储中保存 `conversation_id` 和必要的轻量消息状态；
- 恢复时使用会话 GET 接口取得后端权威历史；
- 会话不存在时清理失效本地记录并回到空会话；
- “新建讨论”清空当前会话和消息，但保留当前项目和图谱选择。

## 轮询规则

- POST 发出后立即启动，首次查询允许短延迟；
- 后端尚未登记进度时，短暂的 `400/404` 被视为启动竞态，不显示业务失败；
- `completed` 或 `failed` 时停止；
- POST 成功或失败后停止；
- 页面卸载、切换项目、新建讨论、重试和开始新一轮时停止旧轮询；
- 同一时间最多有一个进度请求在途；
- 非 `400/404` 的进度请求失败不终止主聊天 POST，可按有限退避继续；
- 主聊天响应是最终回答的权威来源，进度接口只更新过程展示；
- 已过期轮次的进度或回答不得覆盖当前轮次。

## 错误处理

- 缺少问题和图片：不提交；
- 缺少有效项目或图谱：保留输入并提示重新选择项目；
- 能力接口失败：使用与当前后端契约一致的本地静态模式清单，并默认提交 `model_mode: default`；不得继续提交首屏原有的展示占位模型值；
- 图片类型或大小不符合能力接口约束：在提交前提示；
- 聊天请求失败：保留用户消息和输入上下文，显示重试入口；
- 会话返回 `404`：清除失效 `conversation_id`，由用户决定重新提交；
- 响应作用域不匹配：拒绝展示回答并提示安全错误；
- 进度接口临时失败：保留最近进度，不把主请求标记为失败。

## 验证范围

### 单元测试

- 控件值到请求字段的映射；
- JSON 与 multipart 请求选择；
- 第一轮省略、后续轮次携带 `conversation_id`；
- 能力接口模型选项适配；
- 后端回答和历史消息适配；
- 轮询不重叠、正确停止并忽略旧请求；
- 短暂 `400/404` 和其他错误的差异处理。

### 组件和集成验证

- 多轮首屏和按钮样式无视觉变化；
- 五类控件均参与真实请求；
- 第一轮回答和后续追问均能显示；
- 图片、引用、图片分析和视觉证据可显示；
- 切换项目、新建讨论和页面卸载不残留轮询；
- 单轮问答流程保持原样。

### 完成检查

- 相关前端测试通过；
- 生产构建通过；
- 使用运行中的 5000 后端完成至少两轮真实问答；
- 浏览器网络面板确认不存在重复轮询和错误端口请求；
- 对比截图确认现有多轮首屏和按钮工具栏样式未改变。

## 不在本阶段范围

- 不修改 Multi-Discussion 后端接口或模型清单；
- 不重新设计多轮回答区；
- 不修改单轮问答接口和回答 UI；
- 不改变项目、图谱和模拟组会资格规则；
- 不调整 3001 数据平台接口；
- 不处理与多轮接入无关的现有工作树改动。
