# 图谱项目工作台设计

## 目标

把知识图谱项目选择和管理从问答首页迁移到独立的“图谱构建”工作台，同时保持问答首页是产品主入口。用户从文献管理发起构建、在工作台查看 NEXUS 流程、选择已完成图谱进入问答，最终继续证据评估与报告流程。

## 信息架构

侧边栏保留三个主入口：

- 问答首页
- 文献管理
- 图谱构建

`/process/:projectId?` 作为图谱构建工作台路由。没有 `projectId` 时显示项目列表和空状态；有项目时，左侧选中对应项目，右侧复用现有 `MainView` NEXUS 构建流程。切换项目时通过路由参数切换，并以项目 ID 作为组件 key，避免旧项目轮询和页面状态污染新项目。

## 图谱项目列表

工作台左侧从现有后端项目列表读取数据，展示项目名称、状态、进度和操作：

- 点击项目：右侧显示该项目的 NEXUS 步骤。
- 查看进度：与点击项目行为一致。
- 去问答：仅在项目具有有效 `project_id`、`graph_id` 且状态为 `graph_completed` 时显示。
- 删除：所有状态都允许，包括构建中项目。

普通项目删除使用确认提示；构建中项目使用更强的警告。删除有 `graph_id` 的项目时先删除远端图谱，再删除本地项目；没有 `graph_id` 时只删除本地项目。任一步失败都显示错误并保留列表，成功后刷新全局项目监控。如果删除当前项目，路由退回 `/process`；如果它也是问答页记忆的项目，同时清除记忆。

前端只能调用现有删除接口，是否终止后端正在运行的构建任务由后端删除接口语义决定。本次不修改后端代码。

## 创建时命名

从文献管理选择文献并开始构建时，研究问题弹窗增加“图谱名称”字段：

- 根据当前项目名称自动建议 `project_N`。
- 规则为读取符合 `project_数字` 的名称并使用最大数字加一；不存在时使用 `project_1`。
- 用户可以在提交前修改。
- 名称和研究问题都必填，并在前端去除首尾空格。
- 名称写入 pending upload，再通过现有 `project_name` 字段发送给 `/api/graph/ontology/prepare`。

本次不提供创建后的重命名功能，因为当前没有项目重命名后端接口。

## 问答首页

问答首页删除原来的知识图谱项目下拉框，不再加载一个可编辑的项目选择控件。页面顶部只显示当前上下文：

- 有有效项目：显示“当前图谱：项目名称”和“更换图谱”入口。
- 无有效项目：显示“问答需要基于已完成的知识图谱，请先选择或构建图谱。”以及“去图谱构建”入口。

从工作台点击“去问答”时，通过 `projectId` 查询参数和安全的本地选择记忆传递项目。直接从侧边栏进入问答首页时仅恢复上次仍然有效的项目；记忆失效时保持未选择，不自动切换到最新项目。没有有效项目时禁止提交问题。

## 状态同步与错误处理

- 工作台复用全局图谱任务监控，不创建第二套轮询器。
- 删除后主动刷新监控；后台完成事件继续驱动问答上下文刷新。
- 项目切换以路由为单一来源，右侧构建视图按项目重新挂载。
- 删除失败、列表离线、项目失效均显示可见错误，不使用演示数据代替后端结果。
- 项目被删除后，问答页清空失效上下文，不自动重新发送用户问题。

## 测试边界

- 项目名称默认值、递增、规范化和 pending upload 传递使用纯模型测试。
- 删除编排覆盖无图谱、有图谱、部分失败、当前选择清理和构建中项目。
- 工作台覆盖路由选择、项目状态和问答入口资格。
- 问答页覆盖无下拉框、严格恢复选择、失效项目不回退和禁用提交。
- 最终运行全量 Node 测试、Vite 生产构建和 Git 差异检查。

## 非目标

- 不新增或修改后端接口。
- 不实现项目重命名。
- 不实现用户账户、服务端历史问答、文献元数据提取。
- 不改变 CoD 问答、证据评估和报告接口契约。
