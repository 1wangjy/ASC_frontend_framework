# 图谱定向问答前端整合设计

## 目标

将 3000 端口前端的图谱构建与问答流程连通：用户先基于文献构建并命名图谱，构建成功后返回问答首页并自动选中该图谱，后续问题都针对当前选中的图谱发送。

本次工作只修改 `frontend`。5002 端口后端及 `D:\WEB\VScode\yuan ma\桌面\AI4Sci-NEXUS-ASC-Development-Domain-main\backend` 下的代码不得修改。

## 已有后端契约

前端复用现有接口，不要求新增或调整后端接口：

- `GET /api/graph/project/list`：返回后端已有项目；前端只展示包含有效 `project_id` 和 `graph_id` 的项目。
- `GET /api/graph/project/:projectId`：按项目 ID 获取项目详情，保留给现有页面兼容使用。
- 现有本体生成和图谱构建接口：继续产生并返回 `project_id`、`graph_id`。
- `POST /api/graphrag/cod-query`：前端发送 `question`、`project_id` 和 `graph_id`。

开发环境继续由 3000 端口 Vite 服务通过 `/api` 代理访问 `http://127.0.0.1:5002`，不通过修改后端 CORS 实现连接。

## 方案选择

采用“后端项目列表为唯一权威来源”的纯前端适配方案。

未采用以下方案：

- 继续只依赖 `localStorage` 项目注册表：改动较少，但浏览器缓存可能缺失、过期或与后端不一致。
- 复制 3001 前端的完整页面和状态逻辑：容易再次形成两套前端，也会引入无关仿真流程。

`localStorage` 仅保存用户最后一次选择的 `project_id`，不再决定有哪些图谱可用。

## 页面与职责

### 文献管理与图谱构建

- 文献管理页负责选择文献并进入现有图谱构建流程。
- 图谱名称属于构建配置；研究问题不再作为普通图谱构建的前置输入。
- 图谱构建成功且已经获得 `project_id`、`graph_id` 后，普通流程不自动进入仿真环境搭建 Step2。
- 前端跳转到问答首页，并在 URL 查询参数中携带 `projectId`，用于默认选中新图谱。

### 问答首页

- 页面加载时调用 `listProjects()`。
- 对返回结果做兼容归一化，并过滤掉没有有效 `project_id` 或 `graph_id` 的项目。
- 选择优先级为：URL 中的 `projectId`、本地保存的上次选择、列表中的第一个可用项目。
- 用户切换图谱时，只更新当前选择和本地记忆，不修改后端项目。
- 提交问题时必须同时传入当前项目的 `project_id`、`graph_id` 和输入的 `question`。
- 一张图谱允许连续回答多个问题，不将问题写回图谱构建状态。

### 仿真与报告流程

- 保留现有仿真、报告和交互页面，避免扩大本次清理范围。
- 普通图谱构建完成后不自动进入这些页面。
- `simulation_requirement` 继续只属于旧仿真流程，不用于解锁普通图谱问答。

## 数据流

```text
文献选择
  -> 现有本体生成与图谱构建接口
  -> 获得 project_id + graph_id
  -> 跳转问答首页 ?projectId=<project_id>
  -> GET /api/graph/project/list
  -> 自动选中新图谱
  -> 用户输入 question
  -> POST /api/graphrag/cod-query
       { question, project_id, graph_id }
  -> 展示回答、证据和评价入口
```

## 错误处理

- 5002 无法连接：显示明确的后端连接失败信息，并提供重新加载图谱列表的操作。
- 后端没有完整图谱：禁用问题提交，提示用户先到文献管理构建图谱。
- URL 指定项目不存在或没有 `graph_id`：回退到上次选择或第一个可用项目。
- 当前图谱在提问前被删除：保留问题文本，刷新列表并要求重新选择，不自动将请求发送到其他图谱。
- 图谱构建响应缺少 `project_id` 或 `graph_id`：停留在构建页面并显示错误，不进入问答页或仿真页。
- 问答接口失败：保留当前图谱和问题上下文，允许用户重试。

## 预期前端改动范围

实施时优先修改以下前端单元，最终以测试驱动确认实际最小范围：

- `src/views/AscQaView.vue`：使用后端项目列表、处理默认选择与不可用状态。
- `src/api/graph.js`：继续复用现有接口封装，仅在前端契约确有缺口时调整注释或适配。
- `src/features/projects/`：将本地存储职责收缩为“记住选择”，并提供项目归一化/选择逻辑。
- 图谱构建流程的父级页面或控制器：构建成功后跳转问答首页，不自动推进 Step2。
- 对应的前端单元测试与集成测试。

禁止修改：

- 5002 后端源码、路由、数据模型、配置或依赖。
- 3001 前端源码。
- 与本次流程无关的仿真、报告业务实现。

## 测试与验收

### 自动测试

- 项目列表归一化与无 `graph_id` 项目过滤。
- URL、上次选择和默认项目的选择优先级。
- 提问请求包含正确的 `question`、`project_id`、`graph_id`。
- 无可用图谱时禁用提交并显示引导。
- 构建成功后生成正确的问答页跳转目标。
- 构建结果缺少 ID 时不跳转。

### 手动联调

1. 启动现有 5002 后端，不修改其代码。
2. 启动 3000 前端，确认 `/api` 请求代理到 5002。
3. 在 3000 前端选择文献并构建、命名一张图谱。
4. 确认构建完成后回到问答首页，并默认选中刚构建的图谱。
5. 提交两个不同问题，确认两次请求使用相同 `project_id` 和 `graph_id`。
6. 切换另一张图谱提问，确认请求 ID 随选择变化。
7. 确认普通构建流程不再触发缺少 `simulation_requirement` 的 Step2 错误。

## 完成标准

- 3000 前端可通过现有接口与 5002 后端完成图谱列表读取和定向问答。
- 新建图谱完成后可直接进入问答，不需要预先提供研究问题。
- 问答请求不会在未选择有效图谱时发送。
- 后端与 3001 前端没有任何文件修改。
- 前端构建通过，相关测试通过，并完成一次真实的 3000/5002 手动联调。
