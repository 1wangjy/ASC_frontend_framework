# 报告生成与深度互动能力迁移设计

## 1. 目标

把旧 NEXUS 流程中的“报告生成”和“深度互动”从流程页拆出，分别迁入现有侧边栏模块：

- “报告生成”侧边栏负责一个图谱项目的一份报告从创建、生成中、完成到预览和下载的完整生命周期。
- “问答首页”继续使用用户已经完成的整体界面，只接入旧深度互动中后端真实支持的问答、引用、高亮、证据和评价逻辑。
- 只有完成图谱演化并且拥有 `completed` 报告的项目，才有资格进入问答首页的项目选择列表。
- 新模块验证完成后，删除旧流程中的报告生成、深度互动页面和死亡代码，保留网站现有路由框架和侧边栏使用方式。

前端不修改 5002 后端，不伪造后端能力，不自动创建报告或发送问答。

## 2. 已确认的业务主线

每个研究项目遵循唯一主线：

```text
一组文献
  -> 一个图谱项目
  -> 图谱初始化 / 专业构建 / 模拟演化
  -> 图谱演化完成
  -> 一个且仅一个报告
  -> 报告完成
  -> 一个以该图谱和报告为上下文的问答平台
```

核心约束：

1. 一个图谱项目只允许关联一份报告。
2. 报告完成前不能进入该项目的问答。
3. 报告完成后，项目才出现在问答首页的可选项目列表。
4. 用户选择项目后，所有问答请求必须绑定该项目的 `project_id`、`graph_id`、`simulation_id` 和 `report_id`。
5. 侧边栏切换后保留上一次选择；浏览器刷新后先恢复选择，再用后端数据重新校验资格。
6. 报告失败不提供“重新生成”；只允许刷新状态和查看错误，避免产生第二份报告。

## 3. 硬性边界

### 3.1 问答首页界面冻结

`AscQaView.vue` 当前整体页面是用户已经完成的设计，迁移不得改变其常驻布局、视觉层级和已有控件：

- 不重新布局标题、输入框、配置栏、回答卡片、历史问题栏或证据侧栏。
- 不从旧 `Step5Interaction.vue` 搬入新的 LLM 开关、独立 CoD 页、全屏推理画布或额外工具栏。
- 不删除当前模型、框架、推理、本体增强等控件。
- DeepSeek V4 Flash 当前仍是唯一可用模型，但保留原模型选择控件，便于以后接入新模型。
- 只允许改变数据源、接口适配、资格校验、状态管理和现有控件行为。

唯一允许的选择交互扩展是复用顶部现有“当前图谱 / 更换图谱”区域：“更换图谱”点击后打开临时项目选择层，关闭后不占用页面空间、不改变首页常驻布局。

### 3.2 后端能力真实性

- 没有真实接口的功能不能用演示数据伪装成功。
- 接口存在但尚未联调的功能默认不扩展、不主动开放新入口。
- 不修改后端代码、数据库结构或 5002 运行进程。
- 所有真实联调都先读取契约；会创建报告或发送问答的 POST 只能由明确的用户点击触发。

### 3.3 迁移安全

- 新能力验证前不删除旧实现。
- 迁移采用适配层和纯模型，不把旧的超大组件直接嵌入新页面。
- 每个阶段完成后运行聚焦测试、完整测试和生产构建。
- 最后删除旧路由和组件时，再运行一次路由、缓存和真实浏览器验证。

## 4. 报告生成模块

### 4.1 页面职责

`/reports` 从“只列出报告”扩展为报告生命周期中心。它展示两类记录：

1. 图谱演化已经完成但尚无报告的项目。
2. 已经拥有后端报告记录的项目，包括生成中、完成和失败状态。

图谱演化未完成的项目不进入报告中心的可生成列表。

### 4.2 单图谱单报告决策

用户点击“生成报告”时，前端执行：

```text
读取项目关联 simulation_id
  -> 调用 checkReportForSimulation(simulation_id)
  -> 已存在报告：直接使用现有 report_id
  -> 不存在报告：仅本次点击调用 generateReport({ simulation_id })
  -> 保存返回的 report_id / task_id 到当前页面状态
  -> 进入对应报告详情或生成进度
```

前端始终发送 `force_regenerate: false`，并禁止重复点击、自动重试生成和重新生成。网络错误后也先重新检查报告是否已经创建，不能盲目再次 POST。

### 4.3 报告状态与操作

| 状态 | 页面行为 | 可用操作 |
|---|---|---|
| 图谱演化完成、无报告 | 显示项目名称与“尚未生成” | 生成报告 |
| `pending/generating/processing/running` | 显示真实报告和章节进度 | 查看进度 |
| `completed` | 显示保存时间和研究主题 | 预览、下载、去问答 |
| `failed/error` | 显示后端错误 | 刷新状态、查看错误 |

失败状态不显示“重新生成”。

### 4.4 预览与下载

- 预览继续使用已经完成的 `/report/:reportId` 独立阅读页。
- 下载调用现有 `downloadReport(reportId)`，使用后端返回的 Blob，不在前端重新拼报告正文。
- 浏览器下载文件名使用清理过的 `图谱项目名称-研究报告.md`；如果响应头提供合法文件名，则以后端文件名优先。
- 下载失败只显示错误，不回退为前端伪造文件。
- 报告名称统一显示为 `图谱项目名称 · 研究报告`，后端原始标题作为研究主题。

### 4.5 去问答

完成报告的卡片和详情页提供“去问答”：

```text
/?projectId=<project_id>&reportId=<report_id>
```

问答首页加载后必须再次校验这组 ID，而不是因为 URL 存在就默认可信。旧流程中的“进入问答环节”入口删除，不再进入独立深度互动页。

## 5. 问答首页项目资格

### 5.1 合格项目模型

问答首页同时读取真实图谱项目和真实报告列表，构造合格上下文：

```js
{
  projectId,
  graphId,
  simulationId,
  reportId,
  projectName,
  reportStatus: 'completed'
}
```

关联优先级：

1. 报告 `graph_id` 匹配项目 `graph_id`。
2. 报告 `simulation_id` 匹配项目 `simulation_id`。
3. 必要时使用只读 `report -> simulation -> project` 关联补全。

只有报告状态严格归一为 `completed` 的项目才保留。生成中、失败、未知、缺少项目 ID、缺少图谱 ID或缺少报告 ID的记录全部排除。

### 5.2 选择和恢复

- 顶部继续显示当前图谱名称和现有“更换图谱”按钮。
- 点击“更换图谱”时，临时选择层只列出合格项目；列表关闭后首页布局不变。
- 从报告页进入时优先选择 URL 中经过校验的项目。
- 从侧边栏进入时优先恢复上一次选择。
- 本地只保存 `project_id`，不缓存“completed”资格或报告正文。
- 每次页面初次进入、报告列表刷新、图谱任务完成通知或后端返回范围失效时重新校验。
- 上次项目不再合格时清空选择，禁用发送，并使用现有页面提示区域告知用户先完成报告。
- 不自动回退到最新项目，避免用户对错误图谱提问。

### 5.3 问答请求约束

问答适配器在发送前同时校验：

- 当前项目仍存在；
- `project_id` 与 `graph_id` 属于同一个后端项目；
- 关联报告仍为 `completed`；
- 请求绑定的 `report_id` 与当前选中上下文一致。

现有 GraphRAG/CoD 接口继续按后端已支持的 payload 发送；如果后端尚未接受 `report_id`，前端在本地资格模型中保留它，但不擅自把未知字段加入请求。

5002 已经提供 `/api/report/chat`，其当前真实契约使用 `simulation_id`、`message` 和可选 `chat_history`，而不是 `report_id`。因此问答首页通过现有“框架”下拉增加真实的 `Report Agent` 选项：`Hybrid RAG` 与 `NEXUS` 保持现有 CoD GraphRAG 行为，`Report Agent` 使用当前合格项目的 `simulation_id` 调用报告上下文对话。该扩展不增加新的常驻控件或改变页面布局。`report_id` 仍用于资格校验、预览和下载，不发送到后端尚未声明支持的问答字段。

报告问答只使用当前页面会话内最近十条用户/助手消息构造 `chat_history`，不把它宣称为已保存历史。后端响应没有真实引用标识时只显示回答文本，不伪造 R1/R2 或证据映射；没有 CoD `qa_run_id` 时禁用现有 GraphRAG 评价提交。

## 6. 深度互动能力迁移

迁移的是逻辑，不是旧页面界面。

### 6.1 当前可以迁移或复用

- 真实 CoD GraphRAG 请求及项目/图谱范围校验。
- Auto、CoT、ToT 与当前“推理”控件的参数映射，但只开放后端已经确认识别的值。
- Hybrid RAG / NEXUS 与当前“框架”控件的参数映射。
- 当前“本体增强”控件与后端真实模式的映射。
- `<c>R1</c>`、`[R1]` 等引用标记解析为现有回答区域中的可点击引用。
- 图谱节点和 ASC 领域术语的绿色高亮。
- 真实 references / citation_bindings 适配到现有证据侧栏。
- 当前已存在的答案评价入口与后端真实评价接口。
- 当前查询进度、回答结果和证据侧栏状态在侧边栏切换后的保留。

这些能力必须拆成可测试的适配器、引用渲染器和领域术语模型；不得复制 `Step5Interaction.vue` 的整块 UI 或大量内部状态。

### 6.2 暂不新增或需后端确认

| 能力 | 当前决策 | 后端需要明确的契约 |
|---|---|---|
| 新模型 | 保留现有模型控件，不新增假选项 | 模型列表、模型 ID、可用状态 |
| LLM 独立开关 | 不迁移，因为当前问答首页没有该控件 | 如未来需要，明确是否与模型选择重复 |
| 历史问题 | 保留现有区域和布局，不宣称静态示例是真实历史 | 会话列表、详情、保存、删除接口及数据结构 |
| Report Agent 问答 | 通过现有“框架”下拉开放真实选项 | 当前使用 `simulation_id/message/chat_history`；未来如改为严格报告版本问答，再由后端声明 `report_id` 契约 |
| Expert Eval | 仅沿用已经核验的现有入口 | 提交字段、结果读取和持久化规则 |
| LLM Judge | 当前首页没有独立控件，不新增 | 是否由当前评价区触发、模型和返回结构 |
| 完整推理画布 | 不迁移旧全屏 UI | 若以后需要，另立独立功能设计 |

历史栏当前使用的是静态示例问题。迁移阶段不删除其布局，也不把它描述为后端历史；等后端接口到位后，仅替换数据源。

## 7. 状态与页面切换

### 7.1 报告生成

- 报告任务由后端运行，页面切换不会停止任务。
- 前端离开报告页后停止该页自己的短轮询；再次进入时根据 `report_id/task_id` 从后端恢复。
- 侧边栏“报告生成”记住最近访问的报告路径，但不得因为再次进入而重新生成。

### 7.2 问答

- 单次问答沿用现有保活机制，侧边栏切换不能重复提交请求。
- 返回问答首页时保留当前选择、问题、生成状态、回答和证据侧栏状态。
- 浏览器刷新后不承诺恢复正在进行的前端请求；已由后端保存的数据按接口重新读取。后端没有问答任务查询或历史接口时，前端不能假装恢复未保存问答。

### 7.3 图谱演化

- 图谱初始化、专业构建、环境搭建和模拟演化继续由图谱演化模块承载。
- 模拟结束且图谱停止演化后，项目进入“可生成报告”状态。
- 原流程不再继续渲染报告生成和深度互动步骤。

## 8. 旧流程删除顺序

删除必须在新入口验证后进行：

1. 先完善报告中心的资格列表、单报告生成、状态、预览和下载。
2. 再实现问答合格项目模型和上次选择恢复。
3. 在不改问答首页布局的前提下迁移引用、高亮、证据和已支持的推理参数。
4. 用真实报告和真实项目完成报告中心到问答首页的只读/用户触发联调。
5. 将旧流程结束点改为“图谱演化完成 / 前往报告生成”。
6. 移除 `/interaction/:reportId` 路由；旧链接安全重定向到带资格校验的问答首页。
7. 删除 `InteractionView.vue`、`Step5Interaction.vue` 以及只被旧流程使用的样式、状态和工具函数。
8. 搜索并清理旧“Step 4/5”“Step 5/5”“进入问答环节”等死亡文案和引用。

删除阶段不得影响 `/reports`、`/report/:reportId`、`/`、图谱演化路由或现有侧边栏结构。

## 9. 错误与降级

- 报告列表失败：报告中心显示真实错误，不能误显示“没有报告”。
- 报告资格读取失败：问答输入禁用，保留上次选择 ID但不允许发送，等待用户刷新。
- 报告完成但项目关联失败：报告仍可预览和下载，但不提供“去问答”。
- 下载失败：保持当前页面，显示错误，不生成空文件。
- 问答前资格失效：保留用户问题草稿，清空项目选择，不自动重发。
- 引用缺少对应 reference：保留回答文本，将引用显示为不可跳转标记，不伪造证据。
- 后端返回未知模型、框架或推理模式：使用现有默认映射并显示可诊断错误，不静默发送错误值。

## 10. 测试与验收

### 10.1 报告中心

1. 图谱演化未完成的项目不出现在可生成列表。
2. 演化完成且无报告的项目只显示一次“生成报告”。
3. 已有任意状态报告的项目不得再次调用生成接口。
4. 网络不确定状态先检查现有报告，不能重复 POST。
5. 生成中报告恢复真实进度，完成后可预览和下载。
6. 下载使用真实 Blob 和安全文件名。
7. 只有 `completed` 报告显示“去问答”。

### 10.2 问答首页

1. 首页常驻 DOM 结构和当前控件不因迁移发生布局级变化。
2. 项目选择层只包含报告 `completed` 的项目。
3. URL 项目、上次选择和手动选择都必须经过同一资格校验。
4. 切换侧边栏再返回时保留上一次合格项目。
5. 报告状态失效时清空选择、保留草稿且不发送请求。
6. 请求仍严格绑定真实 project/graph scope，不展示错误范围答案。
7. 引用可定位证据，领域术语按原逻辑高亮，缺失引用不伪造。
8. `Report Agent` 使用真实 `simulation_id`，不发送猜测的 `report_id`；单次发送只产生一次 HTTP POST，无真实引用或 `qa_run_id` 时不伪造证据或开放 GraphRAG 评价。
9. 未确认的后端功能不产生可误操作的新控件。

### 10.3 删除与回归

1. 旧 Interaction 路由不再加载旧组件，旧链接可安全回到问答首页。
2. 源码和生产包不再包含旧流程入口和死亡组件。
3. 完整前端测试为零失败，Vite 生产构建成功。
4. 真实浏览器烟测覆盖：报告生成入口、生成状态恢复、预览、下载、去问答、项目恢复、问答引用与证据。
5. 网络审计区分只读验证和用户主动 POST；不能出现自动报告生成、重复问答或图谱重建请求。
6. 变更范围只包含 frontend，后端目录和 5002 服务保持不变。

## 11. 实施拆分

本设计按两个可独立验收的实施波次执行：

1. **报告中心迁移**：资格项目、唯一报告创建、进度恢复、预览、下载和去问答跳转。
2. **问答能力迁移与旧流程清理**：合格项目选择与恢复、现有 UI 内的真实能力接入、旧 Interaction 删除。

第一波完成并验证后，网站仍保留旧深度互动作为临时回退；第二波完成真实验收后才删除旧实现。这样可以保证任何阶段网站都能运行，也便于等待后端补齐历史问题、模型列表和报告增强问答接口。
