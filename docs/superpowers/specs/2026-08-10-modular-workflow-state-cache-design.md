# ASC 分步状态缓存与跨页面流程连续性设计

## 1. 目标

用户通过侧边栏在问答首页、文献管理、图谱构建、环境搭建、模拟推理、报告生成和深度互动页面之间切换时，已经启动的当前阶段必须继续运行。返回原页面后，应显示离开前的界面状态以及后端任务的最新真实进度，不得重新创建项目、重复启动任务或清空已有结果。

本设计只调整前端。现有 5002 后端接口和任务状态仍是业务数据的权威来源。

本设计扩展并替代 `2026-08-10-cross-page-workflow-state-design.md` 中“只缓存问答首页和图谱构建页”的范围，但保留该文档已经确认的单次问答、无额外提醒和刷新边界等规则。

## 2. 已确认的产品规则

- 各阶段之间保持手动推进，不自动串行启动下一阶段。
- 用户明确点击开始、构建、生成或提交时，才允许发送对应的启动型 POST 请求。
- 侧边栏切换只是离开当前界面，不得停止、取消、重启或重新创建任何任务。
- 只有明确点击停止、取消、返回上一步或删除项目时，才执行相应的终止或清理操作。
- 同一网站会话内，返回页面后必须恢复原来的输入、展开状态、进度、日志和已完成结果。
- 后端状态和产物优先于前端缓存；前端不得制造虚假进度、引用或结果。
- 本次不实现节点和关系边搜索，但图谱缓存必须为以后接入该功能保留稳定边界。

## 3. 当前问题

当前各阶段的生命周期不一致：

- 图谱项目已有常驻于 `AscShell` 的 `graphTaskMonitor`，但工作台仍保留页面内轮询和临时界面状态。
- 问答页依赖 `KeepAlive` 保留请求 Promise 和回答界面。
- 环境准备的任务 ID、进度、分析模块、配置和三个轮询器保存在 `Step2EnvSetup` 内，组件卸载时全部停止。
- 模拟推理的状态、完整动作列表和两个轮询器保存在 `Step3Simulation` 内；返回页面时还会再次执行带 `force: true` 的启动请求。
- 报告生成的状态、章节、日志和轮询器保存在 `Step4Report` 内，组件卸载时停止同步。
- 深度互动页面也在卸载时停止 CoD 进度处理。

因此，只增加某一个页面的缓存会继续留下其他阶段的断点；单纯缓存所有大型页面又会导致数据被锁在组件内部、隐藏页面重复轮询和缓存实例无边界增长。

## 4. 方案选择

采用“分步状态缓存 + 分步控制器 + 页面 KeepAlive”的模块化方案。

不采用单一、庞大的全局流程运行器。每一个步骤只管理自己的任务和数据，通过稳定 ID 与相邻步骤连接。`AscShell` 只负责在网站会话期间启动这些模块的同步能力，不承担具体业务逻辑。

不采用纯 `KeepAlive` 方案。`KeepAlive` 只保存页面级界面状态，正在运行的任务状态和轮询必须由页面之外的分步控制器持有。

## 5. 模块边界

### 5.1 通用任务状态

每个分步缓存采用一致的最小状态约定：

```text
key                 当前任务的稳定键
status              idle | starting | running | completed | failed | stopped
progress            后端返回的真实进度
ids                 project_id / graph_id / simulation_id / task_id / report_id / qa_run_id
data                 当前步骤的业务数据
logs                 当前步骤需要展示的日志
error                最近一次真实错误
lastSyncedAt         最近一次成功同步时间
requestGeneration   防止旧请求覆盖新任务
```

控制器统一提供：

```text
startOnce(intent)    只响应明确的用户启动意图
refresh()            通过 GET 同步后端状态
subscribe(view)      页面读取响应式状态
release(view)        页面离开时仅解除订阅
stopExplicitly()     仅由明确停止操作调用
clearExplicitly()    仅由新建流程、删除项目等明确操作调用
```

所有轮询必须单飞：同一任务同一时刻只能有一个状态请求在途。GET 失败可以按现有策略恢复；启动型 POST 不因页面切换、激活或普通网络错误自动重复发送。

### 5.2 图谱构建缓存

复用并扩展现有 `graphTaskMonitor`，保存：

- 当前 `project_id`、`graph_id` 和构建 `task_id`；
- 项目阶段、后端进度、任务错误与同步时间；
- 图谱节点、关系边、类型信息和最后一次图谱快照；
- 工作台需要展示的日志与当前步骤。

现有图谱工作台页面缓存继续保留，用于保存分栏模式、滚动位置、表单内容和展开状态。业务进度仍以图谱分步缓存和后端状态为准。

未来的节点与关系边搜索在图谱模块内新增独立的 `graphSearchModel`。搜索结果只保存节点或关系边 ID，并引用 `graphDataCache` 中的数据，避免复制和过期。当前图谱完整时可本地检索；未来后端提供全图搜索接口时只替换数据适配器。

### 5.3 环境准备缓存

从 `Step2EnvSetup` 移出：

- `prepare_task_id`、准备阶段和真实进度；
- 分析模块、实体类型、模拟配置和图谱成长配置；
- 准备、Profiles、Config 三类轮询；
- 与 `simulation_id + project_id + graph_id` 对应的运行上下文。

返回环境页面时，只订阅已有上下文并同步最新状态。检测到正在运行或已经完成的准备任务时不得再次发送 `/api/simulation/prepare`。

### 5.4 模拟推理缓存

从 `Step3Simulation` 移出：

- 当前 `simulation_id`、运行状态和阶段进度；
- `all_actions`、动作去重集合、阶段增长统计和推理日志；
- 状态与详细动作轮询；
- 图谱成长刷新状态。

从环境页明确点击“开始模拟”时调用一次启动接口。侧边栏切换和页面重新激活只执行状态查询，不得发送 `/api/simulation/start`，不得使用 `force: true` 重启。

返回页面后通过现有 `run-status` 和 `run-status/detail` 恢复。详细接口已有 `all_actions`，因此即使页面暂时没有渲染，也能补齐离开期间的完整动作。

### 5.5 报告生成缓存

从 `Step4Report` 移出：

- `report_id`、`task_id`、生成状态和章节进度；
- 报告大纲、已完成章节、Agent 日志和 Console 日志；
- 状态、Agent 日志、Console 日志三类轮询。

离开报告页不停止报告生成。返回后按已有行号增量同步日志；任务完成后停止轮询并保留最终报告状态。

### 5.6 问答缓存

保留一次只生成一个回答的规则，保存：

- 当前 `project_id`、`graph_id`、问题和设置；
- 进行中的请求、回答、证据、评估状态和草稿；
- 请求版本和失效图谱恢复状态。

页面切换不能增加请求版本、取消请求或重复提交。返回后继续显示生成中、完成或失败状态。

本次状态连续性改造不同时重做回答呈现。后续问答呈现应复用原始前端已有的 `<c>R1</c>` 点击引用和 ASC 领域术语高亮逻辑，不自行生成引用关系。

## 6. 页面缓存与路由规则

需要保留工作状态的页面显式声明稳定组件名，并纳入受控的 `KeepAlive`：

- `AscQaView`
- `DocumentLibraryView`
- `GraphProjectWorkspaceView`
- `SimulationView`
- `SimulationRunView`
- `ReportView`
- `InteractionView`

页面缓存采用每种页面一个受控实例，不按完整 URL 无限创建副本。业务数据由分步缓存按稳定 ID 区分。

处于停用状态的缓存页面不得直接响应全局 `route.params` 变化而清空任务；页面只在激活时读取与自己路由名称匹配的参数，然后订阅对应分步状态。

页面的 `onUnmounted` 和 `onDeactivated` 只能清理 DOM 监听器、ResizeObserver、图形渲染资源及页面订阅，不得停止业务任务控制器。

## 7. 数据流

以模拟推理为例：

1. 用户在环境页点击“开始模拟”。
2. 环境页向模拟分步控制器提交一次明确启动意图。
3. 控制器记录 `simulation_id` 并发送一次启动 POST。
4. 控制器持续通过 GET 获取状态和完整动作。
5. 用户切换到文献管理或问答首页，模拟页面停止渲染但控制器继续持有任务状态。
6. 用户返回模拟页，页面订阅相同 `simulation_id` 的缓存快照。
7. 页面立即显示已有状态，随后显示控制器同步到的最新阶段和动作。
8. 全程不产生第二次启动 POST。

其他阶段遵循同一原则：用户操作负责启动，分步控制器负责运行和同步，页面负责展示。

## 8. 删除、停止与错误处理

- 删除项目时，先调用现有后端删除接口；成功后清除与该 `project_id` 关联的图谱、环境、模拟、报告和问答缓存。
- 删除或切换项目后，旧请求即使晚到也不能覆盖当前项目，所有异步更新必须检查任务键和请求代次。
- 后端暂时不可连接时保留最后一次成功状态，并显示连接异常；恢复连接后继续 GET 同步。
- 启动 POST 返回超时但无法确认是否已创建任务时，先查询状态，不直接重发。
- 显式停止成功后将对应缓存标记为 `stopped`；普通侧边栏切换不得进入该状态。
- 页面缓存被回收时，任务控制器仍由网站会话级模块持有；网站应用真正卸载时停止前端轮询，不伪造后端停止结果。

## 9. 刷新与后端能力边界

本次必须保证同一网站会话内的侧边栏切换不影响任务。

浏览器刷新会重建 JavaScript 上下文。已有状态查询接口的图谱、环境、模拟和报告任务可以根据稳定 ID 重新同步；问答若仍是没有可查询任务 ID 的长连接请求，则只能保证侧边栏切换，不能承诺刷新后恢复进行中的回答。

前端不能可靠地在关闭标签页时强制终止所有后端任务。关闭页面后只停止本地轮询；是否继续执行由后端任务模型决定。本设计不通过不可靠的 `beforeunload` 请求伪装“已停止”。

## 10. 实施顺序

为避免同时重写全部页面，按以下顺序迁移：

### 10.1 本次立即实施范围

本次只交付“同一网站会话内任意侧边栏切换不破坏当前页面任务”的快速阶段，不在本轮抽离完整的分步状态模块：

1. 将所有任务相关页面纳入受控 `KeepAlive`，每种页面只保留一个实例。
2. 为缓存页面补齐稳定组件名和稳定路由键，避免查询参数变化创建无边界副本。
3. 修正缓存页面的路由监听：页面停用时不得把其他页面的路由参数当成自己的空参数，从而清空或停止当前任务。
4. 页面停用时继续保留已经存在的请求与轮询；普通侧边栏切换不得调用任何启动、停止、删除或取消接口。
5. 返回页面时复用原组件实例，不重新执行 `onMounted` 启动逻辑；模拟页尤其不得再次发送带 `force: true` 的启动请求。
6. 浏览器自动化验证问答、图谱、环境准备、模拟和报告页面之间的往返切换，并审计切换期间启动型和停止型 POST 均为零。

这一阶段本身不是临时废弃方案。页面级 `KeepAlive` 仍是最终模块化方案中保存输入、滚动、分栏和展开状态的界面层。后续只把任务状态和轮询逐步从组件迁移到分步控制器，不需要推翻本次路由缓存边界。

### 10.2 后续模块化迁移

1. 建立通用分步缓存约定和受控路由缓存边界。
2. 保留现有 `graphTaskMonitor`，先接入环境准备缓存。
3. 接入模拟推理缓存，移除返回页面时的强制重启。
4. 接入报告生成缓存。
5. 收拢问答请求状态，同时保留现有问答页面缓存。
6. 接入深度互动页需要持续运行的 CoD 状态。
7. 删除已被分步控制器替代的页面定时器和死亡状态，不删除仍服务于纯界面的本地状态。

每一步必须先有失败测试，再进行最小实现；上一阶段验证通过后才迁移下一阶段。

## 11. 验收标准

- 任一阶段运行中切换到任意侧边栏页面，再返回后项目、任务 ID、进度、日志、动作和结果保持一致。
- 图谱构建、环境准备、模拟推理、报告生成和问答在切页期间继续完成。
- 每个明确启动操作最多产生一次对应 POST；普通切页和重新激活产生零次启动 POST、零次停止 POST。
- 模拟返回后不得携带 `force: true` 重新启动。
- 不同项目或任务的迟到响应不能串写状态。
- 删除项目后相关缓存被清除，其他项目缓存不受影响。
- 页面级输入、滚动、分栏和展开状态在同一会话内保留。
- 现有 3000 前端继续通过 Vite 代理连接 5002 后端。
- 自动化测试覆盖各分步控制器、路由激活/停用、单次 POST 和迟到响应。
- 生产构建、全量测试、差异检查通过。
- 浏览器烟测必须确认跨页运行，并审计无额外创建、构建、模拟、报告或问答 POST。

## 12. 非目标

- 不修改后端代码或数据库结构。
- 不新增自动串行执行下一阶段的能力。
- 不实现多用户、历史问答保存或后端任务队列。
- 不在本次实现节点和关系边搜索按钮。
- 不在本次同步重做问答答案的版式、绿色术语或 R1/R2 引用显示。
- 不通过前端缓存替代后端真实状态和持久化数据。
